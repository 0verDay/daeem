# 手牌拖拽总表（2026.11.15 第二轮）

> **★ 2026.11.15 第三轮更新：部队的「操作牌」整套已删除**（连同 3 秒冷却与操作页）——
> 移动 / 锁定攻击 / 行军回到右键，鼠标操作见 [`controls.md`](controls.md)。
> 本文现在只描述仍然存在的拖拽：**建筑牌 / 单位牌 / 将领牌**；
> 其中「生效 / 失败」两套动画仍然适用于它们。

> 本轮把「拖牌」扩成一套**统一手感**：建筑牌 / 单位牌 / 将领牌都走同一个
> `command_card` 拖拽通道（`card_drag_started` / `moved` / `finished`），
> 由 `view/hud.gd` 分派；落点预览画在 `view/overlay_view_3d.gd`。
> ★ 2026.11.15 第三轮：**地图上的 3D 建筑虚影已删除**（用户口径「只需要卡牌虚影」）——
> 建筑牌拖到地图上只淡到 0.72，卡面自己就是虚影；吸附 / 圈仍由 overlay 画。
> 建造那一条的规则细节见 [`build_points.md`](build_points.md)。

## 0. 一句话口径

| 牌 | 拖出后地图上出现 | 落点 | 生效 | 被拒 / 取消 |
|---|---|---|---|---|
| **建筑** | **卡牌自身**（拖到地图上淡到 0.72；没有 3D 建筑虚影） | 建造点位 / 区划中心（城墙） | 牌播生效动画后淡回自己槽位 | 牌飞回 + 闪红（拖回手牌只飞回） |
| **单位**（选中将领时的单位页） | **卡牌自身**（淡到 0.72） | 松手处 = 松手即招募 | 牌播生效动画后按队列重排 | 牌飞回 + 闪红；**松手在任意 UI 上 = 取消** |
| **将领**（无选中时的「将领」页） | **卡牌自身**（淡到 0.72）+ 区划中心亮点 / 底部圈 | 区划中心（圈内） | 牌播生效动画后重排 | 牌飞回 + 闪红；松手在 UI 上 = 取消 |
| **科技**（科技页） | **卡牌自身**（淡到 0.72） | 地图任意处松手 = 启用 / 弃用 | 填充态飞回手牌 | 牌飞回；**松手在任意 UI 上 = 取消，不启用也不弃用** |

## 1. 动画（用户口径）

- **所有牌拖出后同一套透明度**：在手牌里 1.0，拖到地图上 **0.72**，
  拖回手牌范围回 1.0；不再有「某些牌淡到 0 消失」的分支。
- **所有牌同一套放回逻辑**：松手在任意 UI（手牌 / 页签 / 面板）= 取消，
  牌飞回原槽位且**不执行任何动作**；只有在地图上松手才执行。
- **可执行且生效**：卡牌从松手处**向上飘 + 缩小 + 淡出**。
  - 建筑牌：随后**只把自己**在槽位淡回来（`play_drag_success(..., true)`），
    **不重排其他牌**（用户口径「生效后不能全部刷新」；重排会重叠 / 跳动）。
  - 招募牌：队列内容会变（取消牌滑入 / 打出的兵种补回），才走整手牌重排。
- **拒绝执行 / 执行失败**：卡牌**飞回原来的槽位**（`animate_card_back`），
  返程用 **CUBIC** 缓动（不用 BACK：从地图另一头飞回时 BACK 会冲过槽位再弹回来，
  看起来就是「回到手牌后又移了一下」）；返程用 `tween_method` **每帧读当前槽位**，
  手牌在这 0.2s 内重排也能平滑跟到正确位置，末帧精确落位、**不再硬切一下**；
  返程途中再抓起这张牌会立刻中止返程；整手牌重排时也会先掐掉返程 Tween
  （否则两个 Tween 抢同一张牌 = 重叠）。
  整副牌**闪红一次**（`hud.flash_reject`，0.18 秒）。
- **拖回手牌 / 页签 / 面板**：只飞回，**不闪红**（那是取消，不是出错）。
- 两套动画由**不同函数**实现，不要再把「生效」做成「飞回」：
  用户明确要求「可执行和拒绝执行的动画应当是不同的」。

## 2. 将领招募（本轮新增）

- **入口**：什么都没选中时，右下页签栏是 **建筑 / 将领 / 科技** 三颗
  （`PageTabsRes.PAGE_GENERAL`）；「将领」页的内容与「选中区划中心时的招募页」**同一份数据**
  （`_zone_recruit_entries()`），只是条目类型换成 `general_drag`。
- **落点**：拖起时把所有**现在真的能招**的己方区划中心列成锚点
  （`world.can_recruit_zone(kind, zid, faction) == ""`）；指针进入某中心
  `build.drop_radius_tiles`（1.5 格）内 → 吸附、中心出现**底部圈**
  （与建造同一条圈动画：进 0.18s 扩散、离开 0.12s 缩回）。
- **松手**：圈内 = 发 `zone_recruit` 命令（`input_ctrl.request_zone_recruit_at(kind, zone_id)`，
  与点选那条**同一份**命令与校验）；没吸附 = 提示 + 牌飞回。
- **卡面**：将领牌拖到地图上时和建筑牌一样**淡出卡面**（`command_card._fades_when_over_map`），
  否则整张牌会盖住区划中心底部那一圈。
- **钱 / 人口不够**：锚点仍在（规则可招），但圈与亮点是**红**；松手会提示原因并飞回。
- **点选路径保留**：选中区划中心时仍可点招募格（命令带选中的 zone_id）；
  「将领」页里点格只给一句「要拖到中心」的提示。

## 3. 修掉的 bug：单位牌拖回手牌仍招募

旧版 `_on_card_drag_finished` 的 `"recruit"` 分支不看松手位置 ——
把手牌拖回手牌栏松手，牌收回去了、兵却照样出来。现在第一步就判
`hud.point_hits_ui(screen_pos)`：**在任意 UI 上松手 = 取消**（不发命令、不扣钱），
与建筑牌 / 将领牌同一条口径。回归测试在 `tests/test_ui.gd`（`_test_recruit_via_card`）。

## 4. 虚影 / 圈的状态在哪

- HUD（逻辑 + 吸附，唯一判据）：
  - 建造：`drag_build_active/type/anchors/anchor/tile`；
  - 招募：`drag_recruit_active/kind/anchors/anchor/tile`；
  - 交给 overlay 的统一状态：`drag_anchor_active/kind/tiles/tile/ok/radius`。
- Overlay（纯画）：`drag_anchor_*` + `_ring_anim`（格 → {t, r, color}），
  `tick_drag_rings(dt)` 每帧由 `game_scene3d._process` 推进（暂停传 0 = 冻住）。
- 卡牌虚影：`command_card._set_drag_face_alpha()` —— 建筑牌拖到地图上停在 `0.72`；
  拖回手牌淡回 1.0。**没有 3D 建筑虚影节点**（`BuildCardGhost` / `WallRingGhost` 已删除）。
