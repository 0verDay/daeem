# 手感优化计划（2026.11）

> 目标：在不改玩法规则、不破坏确定性与联机的前提下，优先提升「跟手、看得懂、指挥顺手」三件事。
> 本文只做计划与落点分析，不改代码。所有数值优先进 `data/config.json`，代码里不写死。

---

## 0. 结论摘要

这个项目的手感基础已经很扎实：路径拉直 / 拐角圆化、软碰撞与拥挤认账、按兵种分带的阵型、立牌命中区 + 框选容差、触摸手势、插旗 / 攻击标记 / 受击闪白 / 镜头跟随将领、按钮按下与悬停动效、音效节流，都已经做过一轮手玩打磨。

**当前最大的手感缺口不在「玩法」，而在四类「中间层」：**

1. **相机**：跟随镜头读的是逻辑坐标 `u.pos`（移动端 30Hz 逻辑下会一跳一跳）；程序性移动（双击跳镜头、小地图跳转）是瞬移；缩放没有缓动；**移动端完全没有缩放入口**。
2. **选择时序**：左键在**按下那一刻**就处理选中 / 清空选中；拖框到一半按 Esc 时，「不动已有选中」实际上做不到（按下时已经清掉了）。
3. **反馈**：桌面端没有攻击 / 建造 / 无效目标的光标状态；命令被拒只有一行红字；单位死亡瞬间消失；立牌移动没有行走微动。
4. **指挥效率**：没有 Shift 指令队列、没有玩家可用的巡逻 / 原地驻守、没有编队（控制组）、城墙不能拖拽连造。

建议先做 **P1（跟手）+ P2（反馈）**，这两块改动集中、风险低、体感提升最大；P3 涉及逻辑层与联机，单独排期。

## 3. 分阶段实施

### P0 · 基线（0.5 天）

先量再改，避免「凭感觉调完更差」：

- 录一组基线：右键下令到单位起步的延迟、镜头跟随的抖动幅度、移动端 30Hz 下镜头步进、命令帧耗时。
- 复用现有套件：`tests/test_view.gd`、`test_selection_range.gd`、`test_path_feel.gd`、`test_formation.gd`、`test_touch.gd`、`test_time_step.gd`。
- 新增 `tests/test_feel.gd`（纯断言，不依赖截图）：
  - 镜头跟随在 `render_alpha=0.5` 时对准的是插值位置；
  - 缩放前后光标锚点的屏幕位置误差 < 1px；
  - 拖框 + Esc 后选中集合与按下前一致；
  - 空地单击的取消选中发生在松手；
  - 双击同类选中的集合正确；
  - （若做队列）Shift 追加的路点顺序正确。

### P1 · 跟手（1.5~2 天）

1. **跟随镜头插值**：`game_scene3d.follow_unit` / `_camera_update` 改用 `world.render_pos_of()`（没有该方法的对象回退 `.pos`）。
2. **程序性移动缓动**：给 `center_on_tile_precise` / 小地图跳转 / 双击跳镜头加一个短缓动；**拖拽、方向键、边缘滚屏仍保持 1:1**，否则会觉得「镜头拖不动」。
3. **边缘滚屏起停缓冲**：当前速度是瞬间给满 / 瞬间归零；加 0.06~0.10s 的起停斜坡，贴边时更顺。
4. **缩放缓动 + 细档**：`zoom_at` 记录目标 zoom，每帧向目标插值并重新保锚点；`zoom_step` 1.12 → 1.06~1.08（先做成配置）。
5. **选择时序修正**：
   - 按下时保存 `_press_selection_snapshot`；
   - 空地清空选中延后到 `_finish_drag` 且 `not drag_active`；
   - `_cancel_drag` 恢复快照；
   - 单位上的「按下即选」保留（这是现在的爽点）。
6. **双击同类**：左键双击己方单位 → 选中当前屏幕内同 `unit_type` 的己方单位（仍走 `select_units` 展开整队）。

**验收**：移动端镜头跟随不再一跳一跳；双击跳镜头不生硬；拖框 Esc 能回到原选中；缩放锚点稳定；现有选择相关测试全绿。

### P2 · 反馈（2 天）

1. **光标状态机**（桌面）：`input_controller` 输出一个 `cursor_mode`（`normal / attack / build / invalid / order`），由场景设置光标；攻击模式 / 悬停敌人优先。
2. **拒绝反馈**：`order_rejected` / `build_rejected` 在落点播红色短环 + 轻音效；命令卡对应格闪红 0.15s。
3. **死亡演出**：新增一个纯表现层（类似 `charge_fx_view_3d`），监听 `kill` 事件，播 0.25s 烟尘 / 碎片；不改逻辑。
4. **行走 / 攻击微动**：`unit_view_3d` 在写 MultiMesh 变换时，按 `u.id` 派生相位加微小上下浮动；攻击瞬间加前冲回弹。全部是渲染偏移，不碰 `u.pos`。
5. **移动端 HUD 插值**：读条 / 冷却在两次刷新之间本地推进，避免 10Hz 跳格。

**验收**：悬停敌人光标变攻击；点不动的地方有红环；打死人有烟尘；行军时立牌有轻微起伏；录屏对比能明显看出「更活」。

### P3 · 指挥效率（3~4 天，单独排期）

1. **Shift 指令队列**（先做单机，再评估联机）：
   - `unit` 增加 `order_queue`（只存可序列化的点 / 目标 id）；
   - `command_processor` 增加 `queue` 标记或独立 `queue_move`；
   - 到达 / 目标消失后自动取下一条；
   - 地面画编号路点，`order_flag` 只显示最新一条；
   - 联机：队列是权威状态，快照是否同步需要单独确认（客户端至少要看到路点）。
2. **编队 / 控制组**：先解决键位冲突（数字 1..6 已被将领槽位占用；Ctrl+1 / Ctrl+3 是开发者快捷键）。建议 `Alt+数字` 或 `F1..F6`，需要拍板。
3. **巡逻 / 驻守**：操作页加两格，复用 `order_group_attack_move` 与 `hold_position`。
4. **城墙拖建**：建造模式按住左键拖线，按格连续下发 `build`；预览每格是否可建 / 钱够不够。

### P4 · 移动端（2 天，需先拍板交互）

1. **缩放**：三选一——
   - 三指捏合（双指保留框选，最不冲突）；
   - 小地图旁 `+ / -` 按钮（最直观，但占 UI）；
   - 双击后按住上下拖动（手势隐蔽，需要教学）。
2. **取消选中**：空白处加一颗明确的按钮，或长按空地取消。
3. **触摸命中**：复核 `box_select_pad_px` / `unit_pick_pad_px` 在手机小屏上的手感；必要时按屏幕 DPI 微调。
4. **可选**：下令成功时 `Input.vibrate_handheld(15)` 轻震（只在移动端，配置开关）。

### P5 · 打磨与回归（1 天）

- 所有新数值进 `config.json` + `logic/config.gd` 的缓存字段；
- 跑全量测试 + `bench_fps_3d` / `bench_crowd`；
- 手玩清单：跟手 / 选中 / 下令 / 战斗 / 移动端各过一遍；
- 文档补 `docs/README.md` 的「手感」一行与 `pitfalls.md` 新坑。

## 5. 建议先做的 5 个 Quick Win

按「半天内能做完、体感立刻变好」排序：

1. **跟随镜头改用 `render_pos_of`**（移动端 30Hz 抖动直接消失）。
2. **空地取消选中延后 + Esc 恢复快照**（修掉「拖框反悔丢选中」）。
3. **缩放 / 跳转缓动 + 滚轮步长细化**（镜头不再硬切）。
4. **光标状态 + 命令被拒红环**（「点下去有没有生效」一眼可见）。
5. **死亡烟尘 + 行走微动**（战斗与行军不再像贴纸）。

## 6. 验证与度量

- **自动**：`tools/run-tests.ps1` 全量；新增 `tests/test_feel.gd` 覆盖 P0 列的六条不变量。
- **性能**：`tests/bench_fps_3d.gd`（开窗实机）、`tests/bench_crowd.gd`（逻辑）；确认行走微动 / 死亡层不增加 draw call 批次。
- **手玩**：每阶段结束录一段 30 秒同场景对比（移动端 + 桌面各一），重点看「镜头是否跟手、点选是否准、下令是否有回应」。
- **回归红线**：不改 `logic/` 的确定性；不在 `view/` 里写玩法规则；新数值必须可从 `config.json` 调。
