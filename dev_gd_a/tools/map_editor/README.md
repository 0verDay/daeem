# DAEEM 地图编辑器

给 Godot 版（`dev_gd_a/daeem/`）画地图用的**小工具**：Python + tkinter 写的，
**零第三方依赖**（Windows 自带的 Python 直接能跑），不进游戏包。

做它是因为 `logic/zone.gd` 顶上一直挂着这句话：

> 「具体的区块划分后续在地图编辑时给出，现在自由写占位逻辑。」

于是现在有了这个编辑器 —— 它导出的地图 JSON，游戏直接读。

---

## 一、怎么打开

### 双击打开（推荐）

直接双击 **`dev_gd_a/tools/map_editor/map_editor.bat`** 就行，不用敲命令行：

- 默认打开工程里的 `data/test_map.json`；
- 想开别的地图：**把那张 JSON 拖到 `map_editor.bat` 上**；
- 找不到 Python（或 Python 缺少 tkinter）时，它会**停住并给出提示**，不会一闪而过。

> `.bat` 里踩过的四个坑都写在文件头部注释里（`start "" pythonw` 才不会被黑框连坐杀掉、
> 路径要先消掉 `..`、目录层数不能少一层、行尾必须 CRLF）—— 改它之前先读那几行。

### 命令行

```powershell
# 打开一张空白画布（24×16，全是虚线格）
python dev_gd_a/tools/map_editor

# 直接打开现有地图（相对 dev_gd_a/daeem/ 或当前目录都认）
python dev_gd_a/tools/map_editor dev_gd_a/daeem/data/test_map.json
python dev_gd_a/tools/map_editor data/test_map.json

# 不开窗口，只跑一遍数据层自检（读 config / 读地图 / 导出再导入）
python dev_gd_a/tools/map_editor --selftest
```

要求：Python 3.8+（实测 3.14 通过），tkinter 可用（Windows 官方 Python 自带；
Linux 上要装 `python3-tk`）。

## 二、导入 / 导出按钮

**在右上角**，一组三颗，前面有「地图文件」四个字做分组标题：

| 按钮 | 作用 | 快捷键 |
|---|---|---|
| **导出 JSON** | 把当前地图写成 Godot 直接读的 JSON（强调色，最常用） | `Ctrl+S` |
| **导入地图…** | 打开一张已有的地图 JSON（老地图也认） | `Ctrl+O` |
| **新建地图…** | 重开一张全虚线格的空白画布（**不问尺寸**，见第三节） | `Ctrl+N` |

导出前如果地图有毛病（没地块 / 没设大本营 / 大本营在山上 / 有空区块），会先提醒一句，
**不阻止**导出 —— 半成品地图随时可以存下来接着画。

## 三、画布：一张无限大的虚线地图

打开编辑器看到的是一张**铺满虚线格子的无限画布** —— 没有边框、没有「地图边界」，
滚到哪都能接着画。初始地图的内存网格是 0×0：不点就没有任何地块。

- 画布上**只有虚线格子**：没有实心网格线、没有背景棋盘格花纹（需求明确要求的）。
  已建出来的地块是实心的地形色，虚线格就是「这里可以点一下建地块」。
- 内存里的网格会**按需生长**（点远处就朝那边长，只长到装得下 + 一点余量），所以「画到很远的地方」
  不会卡；导出范围永远是**已画地块的包围盒**（见第六节）。
- 四个方向都能画：**往左上画就是负坐标**（模型里靠网格整体平移装下来，见第三节的「坐标」一节）。
- 兜底边界是 `±4096` 格（`model.MAX_COORD`）：比一张 RTS 地图大两个数量级，正常画图撞不到。
  它**不是隐形的**：接近边界时状态栏会提醒，撞上了会明说「超出可用范围（哪个方向、多少格）」。
  （要真·无上限得把内存网格换成稀疏存储 —— 见第九节，那是一次数据层重写。）

> **编辑器里没有「地图尺寸」这个概念**（刻意去掉的）：地图可以是不规则形状
> （画个 L 形、八边形都行，内部不会缺格），边界永远等于**已画地块的包围盒**，
> 导出时编辑器自己把它搬到左上角 (0,0)。让人先填一个「宽 × 高」再往里画纯属多余，
> 而且填小了会把画好的地裁掉。

### 平移与缩放

| 操作 | 结果 |
|---|---|
| **按住空格 + 左键拖动** | 平移视野（光标变手形；松开空格回到画地块） |
| **中键拖动** | 同上（不用按空格） |
| **方向键** | 平移视野：按 `←` 视野往左走、按 `→` 往右、`↑` 往上、`↓` 往下 |
| 滚轮 | 以**光标为锚点**缩放 |
| `F` | 适应视野（看全已画的地块）；空地图就是回到原点 1:1 |
| `G` | 跳到已设的大本营 |

> 方向键的方向是「看地图」的直觉：按 `←` 就把视野往左推（地图内容整体右移）。
> 方向表只有一份（`app.EditorApp.ARROW_PAN`），按键绑定与测试都读它，不会两处不一致。

### 为什么它跟手（这几个开关别随手关掉）

拖动/缩放要跟手，靠的是下面这些（每一条都有实测数字，见第十节）：

| 开关 | 作用 | 不做会怎样（实测） |
|---|---|---|
| `request_redraw()` 合并重绘 | 鼠标一秒能发上百个事件，同一帧里只重画一次 | 拖动 100 个事件要 **2 秒** |
| `refresh_tile_panel()` 就地改值 | 改一格属性不重建侧边栏，只改那几个控件的文字/颜色 | 点一下地 **18~31 ms**（整条侧边栏销毁重建） |
| `refresh_zone_panel()` 就地改值 | 区块页划一格 / 换选中项 / 改名字只改那一行与图例 | 每一下重建一页（要重 new 一个 24 行 Treeview，**300+ ms**） |
| `set_page()` 里的「同一页直接返回」 | 点自己已选中的页签不做任何事 | 白重建一页（点了像卡一下） |
| `HOVER_THROTTLE_MS = 16` | 划过一格的高亮最多落后光标一帧 | 40 ms 时节流，高亮肉眼可见地「在追鼠标」 |
| 拖动时清掉 `hover` | 平移时鼠标底下的格子一直在换，留着就会画出一个跟不上的高亮框 | 拖动过程中高亮一闪一闪 |
| `BIG_CELL_PX = 22` | 格子缩到 22px 以下就改用「一整张虚线网格」画 | 0.6 倍时一屏 1825 个虚线框、单次重绘 **7.8ms** |
| `MIN_GRID_PX = 11` | 格子再小就不画网格了（那个尺寸也看不清） | 0.4 倍时要画 4000 格、**20ms**；0.1 倍要画 8.8 万格、**420ms** |

顺手还去掉了「被地块盖住的虚线框」（有地块的格子不再画虚线框，白画几百个图元）。

### 坐标：世界坐标 vs 数组下标（改代码前必须先搞清这一条）

编辑器里有两套格子坐标，**混用会出很隐蔽的 bug**：

| | 是什么 | 谁在用 |
|---|---|---|
| **世界坐标** | 设计师看到的绝对坐标，`(0,0)` 是画布起点，往左上画就是负的 | 鼠标点击、状态栏、属性面板、区块的 `tiles`、大本营、导出 |
| **数组下标**（view） | 内存网格里的 `0 … cols-1`，`ox/oy` 这个视野偏移是按它算的 | 重绘、`visible_tile_range()` |

两者相差一个 `origin`（`MapModel.origin_x/origin_y`：世界 `(0,0)` 落在数组哪一格）。
换算只有两个方法：`MapModel.view_of()` / `world_of()`，界面上再加一层
`EditorApp.world_to_view()` / `view_to_world()`。

- **往左上画**的机制：要在世界 `x=-1` 落笔时，把整张数组**右移一格**、`origin` 加一，
  于是老内容的世界坐标一格都没变、画面上什么都不动（只有数组下标变了）。
- **平移时不许动的东西**：区块的 `tiles` / `center`、阵营的 `faction_bases` ——
  它们是世界坐标，`origin` 一变，`view_of()` 自动算出新下标，两者仍然对得上。
  **曾经在这里错过一次**：把 `zone.tiles` 也加了偏移，于是「世界坐标里的同一格」悄悄变成了另一格，
  表现是「往左上画第三格之后，前两格的区块归属没了」（`test_model` 现在钉住了这条）。
  ⚠️ 区划中心是**后加的**，也在这条规矩里：`_resize()` 会把出界的中心忘掉并重建反查表。
- **改尺寸/平移之后必须重算一遍 `zone_of`**：它的键是数组下标，而大小与 `origin`
  都变了 —— 唯一的稳妥做法是「照 `zone.tiles`（世界坐标）重新登记一遍」，
  不要手工搬下标（踩过两次：用新 `cols` 拆旧下标、以及 `origin` 还没改就登记）。
- **可画范围是不对称的**：判据只有一处 `MapModel.can_draw_at()`。
  数组下标 = 世界坐标 + `origin`，而 `origin` 会随着往左上画变大 ——
  所以往左上画得越多，**右上方向的余量越小**（两边互相挤）。
  状态栏的「离边界还剩几格」直接用 `draw_room(x, y)`，别在界面里另写一份公式
  （踩过：用 `abs(x)` 算距离，在不对称的图上永远算不到边界）。
- **建地块时画面不许动** —— 这是最反直觉的一条，符号方向错过一次：
  格子画在屏幕上的位置 = `ox + (世界坐标 + origin) × 格子大小`。
  往左上画会让模型把 `origin` 加 `S`（数组整体右移/下移给负坐标让位），
  所以视野偏移必须**减** `S × 格子大小`（`EditorApp._follow_origin_shift`）。
  写成 `+=` 的症状就是用户报的那句「**创建空白地块时会自动移动视角**」：
  画面往右下跳两格（origin 一格 + ox 一格），鼠标点的地方和地块出现的地方还错开了。
  `test_app.py::t_draw_up_left_no_invisible_wall` 现在钉住两条：
  ① 已画好的格子在屏幕上一格都不动；② 新格子就出现在点下去的那个屏幕位置。
- **导出与绝对坐标无关**：导出永远取已画地块的 AABB 并搬到 `(0,0)`，
  所以「画在原点左上」照样能正确导出（见第五节）。
  已经手工验过一整条链：画（含负坐标）→ 导出 → 读回来 → 再导出，**JSON 逐字节一致**。

### 兜底边界到底是多少（别让人撞上「隐形线」）

| | 值 | 说明 |
|---|---|---|
| 数组下标上限 | `MAX_COORD = 4096` | `-4096 ≤ 下标 < 4096`。数组是**稠密**的，这个尺寸约 150 MB |
| 世界坐标可画范围 | `[-4096-origin, 4095-origin]` | 往左上画会让 `origin` 变大，右上方向的余量随之变小 |
| 内存安全网 | `MAX_GRID_BYTES = 512 MB` | 正常情况下撞不到（上限之内最大也就 ~150 MB）；它拦的是「以后有人把 `MAX_COORD` 调大」 |
| 导出大图提醒 | `BIG_MAP_WARN_TILES = 512` | 包围盒超过 512×512 时导前提醒一句（**不阻止**） |

撞到边界时**不是默默拒绝**：状态栏会说「超出可用范围：往左还能画 N 格、往上 M 格…」，
鼠标划过接近边界时也会提示「离可用范围边界还剩 N 格」（`LIMIT_HINT_MARGIN = 64`）。
—— 用户当初报的「隐形线」，根因就是**只有点击时才提示一句、画面上什么都看不见**。

## 四、怎么画一张地图

### 1. 建地块 / 看属性（「地块」页签）

**左键一手包办**：点虚线格 = 在这儿建一块空地；点已有地块 = 看它的属性。地形**只能**在属性面板里选。

| 操作 | 结果 |
|---|---|
| **左键点虚线格** | 建出一个**空白地块**（默认草地），并立刻在右侧「地块属性」里打开它 |
| **左键点已有地块** | 属性面板切到这一格（**不会**顺手改地形 —— 没有笔刷） |
| **右键点已有地块** | 把这一格**变回虚线格**（删掉它；区块归属也一起摘掉） |
| **右键点虚线格** | 什么都不做（从零建一格永远走左键） |
| **`Shift` + 拖拽** | **框选**一个矩形里的地块（见第 5 小节），批量改地形 / 归属 / 删除 |
| 改地形 | 在属性面板里点「草地 / 森林 / 山地」三颗彩色按钮（改的就是**面板正在看的那一格**） |
| `Ctrl+Z` / `Ctrl+Y` | 撤销 / 重做（右键删掉的地块也能撤销回来） |

> **为什么不是画笔**：需求是「左键点虚线格 = 建空地，左键点已有格子 = 开属性面板，在其中选地形」。
> 于是创建与编辑分成两件事，地形也没有「当前笔刷」这个状态 ——
> 不会出现「手一抖把一片地刷错」，而且每块地是什么地形都得明确选一次。
> **要批量改就用框选**（改哪几格是画出来的，不是刷出来的）。

虚线格 = **地图外**的格子：它没有地形、不能站人。地图可以不是矩形（画个 L 形、八边形都行），
但内部不会缺格 —— 缺格就是「地图外」，在游戏里一律不可通行。

> **区块名画在四个角上**：每个区块的**左上 / 左下 / 右上 / 右下**四格里各写一份名字，
> 用半透明的字（画布底色与区块色混出来的中间色；tk 的文字没有 `alpha`，只能算颜色）。
> 为什么要四份：区块可以大到一屏放不下，只写一份的话滚到别处就不知道看的是哪个区。
> 两个细节：**包围盒的角不属于这个区块时不写**（区块是逐格分配的，非矩形的角上可能是
> 别人的地或虚线格），**格子小于 `ZONE_NAME_MIN_PX`（26px）时整个不画**（字会糊、图元还翻倍）。
> 实现见 `app.py` 的 `redraw()` 4d 段与常量 `ZONE_NAME_ALPHA`。

### 2. 地块属性面板（右侧边栏，点一下格子就出现）

**左键点任意格子**（虚线格会先建出来）→ 右侧边栏就是这一格的属性，里面能：

- 看这格的坐标、地形、属于哪个区块
- **选地形**（三颗带颜色的按钮：草地 / 森林 / 山地）—— 地形只有这一个入口
- 改「归属区块」（下拉框，含「不属于任何区块」）
- 把大本营设在这里 / 取消
- **删除这个地块**（变回虚线格；删掉时它从所属区块里一并摘掉）

> 面板里的按钮是**就地改值**的（不重建控件），所以连点几下改地形、换大本营都不会卡。
> 只有「虚线格 ↔ 有地块」这种面板结构本身的切换才会重建一次（见第十节）。

### 3. 划区块 + 设区划中心 + 配产能（「区块」页签）

1. 切到上边栏的**「区块」**页签 → 侧边栏出现区块列表
2. **新建区块**（默认名「区块1号」，可以改成「东关」这种）；**删除** / **双击重命名** / 在输入框里改名字
3. **在列表里选中一个区块**（列表里会标出来哪个正在划分）
4. 左键点地块 → **划给它**；再点一次 → **从它里面移除**
5. **设区划中心**：左键点它自己的一个地块（面板会切到那一格），
   再按侧边栏的 **「把中心设在这一格」** —— 再按一次 = 取消；
   想在别处就在那一格再点一次按钮（**中心跟着挪过去，永远只有一个**）

| 操作 | 结果 |
|---|---|
| 「把中心设在这一格」 | 只有**这一格属于这个区块**时才可点（否则按钮是灰的）；一格只能是一个区块的中心 |
| 中心与大本营同格 | 两栋建筑会叠在一起，所以**互相排斥**：先设的留下，后设的被清掉（大本营优先） |
| 删地块 / 删区块 | 中心一起忘掉（不会留下一个指向虚线格的中心） |

**产能**在同一个面板的「产能」一节里填，三档：**粮食产能 / 黄金产能 / 人口产能**，
单位统一是 **n 资源／地块／秒**（0 = 不产出）：

- 填完按 `Enter` 或点到别处就生效；乱打字**不会**把原值弄坏（会恢复成原来的数）
- 负数会被夹成 0，超大值会被夹到上限（只挡误输入，不是平衡数值）
- 导出时**只有配过非零产能的区块**才写 `production`（老图导出后仍然干净）

**区划中心是什么**：游戏里它落成一栋**中立障碍建筑** ——
占满一整格、**任何阵营的单位都进不去**、无血量、无敌、没有攻击手段、也不能拆；
**左键点它**会显示这个区划的详情（区划名 / 归属 / 区划大小 / 三档产能 / 人口）。
所以：**每个区块都要有一个中心**，这是导出前的**硬规则**（见第七节）。

其它：侧边栏有「清空这个区块的地块」（地块还在，只是没归属）与「把清空后的地块变回虚线格」
（连地块一起删）。区块可以是非矩形的，也可以先把区块建好、地以后再划；
地图上一个地块都没有的区块**仍有名字**，导出后在游戏里是一个空区块（不会抢资源）。

> 区块页签的逻辑与从前一字未改（左键逐格点选 / 再点取消；右键在区块页不做事）。
> **「区块」与「区划」是同一个东西**（旧文案叫区块、用户的说法叫区划），别当成两个概念。

### 4. 给阵营配大本营（「阵营」页签）

分阵营对战的地图，每一方要有**自己的**大本营。
**老式大本营（那个单独的「默认点位」）已经彻底删掉了** —— 现在只有这一套。

1. 切到**「阵营」**页签 → **新建阵营**，填它的 **id**（游戏里的名字：`p1`…`p8` / `enemy`）
   —— 名字与颜色随便起，id 必须对得上游戏
2. 在列表里**选中一个阵营**
3. 到「地块」页签**左键点一格**（把它选中）
4. 回「阵营」页签，按 **「把大本营设在这里」** —— 大本营就落在那格；再按一次 = 取消

| 操作 | 结果 |
|---|---|
| 新建阵营 | 弹框填 id（默认给下一个没被占用的 `p1`…）；名字与颜色自动给一份 |
| 改名 / 换色 | 选中的阵营在详情里改（颜色只影响**编辑器显示**，游戏读 `config.json` 的颜色） |
| 设大本营 | 先在「地块」页签选一格，再回来按按钮；一格只能属于**一个**阵营（被抢时原来那方自动失去） |
| 取消大本营 | 对同一个大本营再按一次按钮 |
| 删除阵营 | 它的大本营一起忘掉 |

- 地图上每个阵营的大本营画成一块**阵营色方块**（中间写 id），一眼看得出哪块是哪一方的。
- **每个阵营都必须有一个大本营** —— 这是导出前的**硬规则**（见第七节），缺了会挡住导出。
- 大本营落在山地 / 虚线格上时不阻止，但会提醒：游戏里会就近换一个能站的格子。
- 阵营 id 写错（游戏不认识）也会提醒 —— 那条大本营在游戏里不会生效。

> ⚠️ 阵营 id 就是 Godot 的阵营字符串，**没有数字映射**：导出的 `faction_bases`
> 以 id 为键，游戏按 id 直接查得到，双方都不需要翻译表。

### 5. 框选一批地块批量改（`Shift` + 拖拽）

「地块」页签里按住 **`Shift` 拖出一个矩形** → 矩形里的**已有地块**被选中（虚线格不选），
右侧面板变成「批量」模式：

| 操作 | 结果 |
|---|---|
| 三颗地形按钮 | 把**选中的全部地块**改成那种地形（选中的地形不一致时不打勾） |
| 归属区块下拉框 | 把选中的全部地块划给某个区块 / 一起摘出来（不一致时显示「（多个值）」） |
| **删除选中的 N 个地块** | 变回虚线格（会先确认） |
| 点地图任意处 | 退出框选，回到单格属性 |
| `Esc` / 「取消框选」 | 只取消框选（不动数据）；再按一次 `Esc` 才回地块页签 |

- **一次批量操作 = 一步撤销**（`Ctrl+Z` 整批退回，不是一格一格退）。
- 拖框时画的是虚线预览，松手后是实线框 + 角上写「N 格」（不用自己数）。
- 平移仍然是**中键拖动 / 空格 + 拖动 / 方向键**；不带 `Shift` 的左键拖拽什么都不做。
- **`Shift` 怎么算「按住」**：键盘事件与鼠标事件的 `state` 位**两条都认**（取「或」）。
  - 只信鼠标 `state` 会漏 —— tk 不保证它带 Shift 位（实测见过 `0x0`）；
  - 只把 Shift 绑在画布上也会漏 —— **侧边栏点过之后焦点就跑过去了**，
    画布上的 Shift 绑定根本不响。所以 Shift 的按下 / 松开绑在 **root + canvas 两处**
    （`_bind_shift_keys()`）：焦点在哪儿都收得到。
  这两条缺任何一条，表现都是**静默不框选**（用户先后报过两次，见 `docs/pitfalls.md` 5.26 / 5.32）。

### 6. 导入 / 导出 JSON

- 右上角 **导出 JSON**（`Ctrl+S`）→ 写出一张 Godot 直接读的地图
- 右上角 **导入地图…**（`Ctrl+O`）→ 读现有地图（老板地图也认，见第六节）
- 右上角 **新建地图…**（`Ctrl+N`）→ 直接给一张全虚线格的空白画布（**不问尺寸、不问起始地形**）

导出前会分两层检查（**先拦后提醒**）：

**硬规则（拦住，什么都不写）** —— 见第七节：每个阵营必须有大本营、每个区块必须有中心。

**提醒（确认后照导）**：没有地块、有区块没地块、中心落在山上 / 与大本营叠格、
大本营落在山上、阵营 id 游戏不认识、地图特别大。

> ⚠️ 老式大本营那个「默认点位」已经没有了，所以也**不会再弹**「大本营点位没设」这种
> 「让人去改本来没问题的东西」的警告（用户报过一次：所有阵营的大本营都设了，
> 却因为那个单数字段没填而弹警告）。现在的规则简单直白：**每个阵营都得有一个大本营**。

### 顺手做的那些

| 操作 | 结果 |
|---|---|
| `Ctrl+Z` / `Ctrl+Y` | 撤销 / 重做（上限 200 步）。**区划中心与产能也在撤销栈里**（改错了能退回去） |
| 「全部清空」 | 把所有地块变回虚线格（区块与阵营保留） |
| 状态栏 | 光标下的格子（坐标 / 地形 / 区块）、地块总数、区块数、`大本营 n/m`、`区划中心 n/m` |

> ⚠️ 目录里**没有**「地图尺寸」那一栏了：导出范围永远是已画地块的包围盒
> （所以也没有「铺满这个范围」「裁剪到画布」这两颗按钮）。

## 五、导出的 JSON 长什么样

就是 `data/test_map.json` 那一套，**多加两张网格 + 阵营那块**：

```json
{
  "cols": 17,
  "rows": 22,

  "exists": [[1, 1, 0, ...], ...],      // ★ 1 = 这个格子存在；0 = 地图外
  "layout": ["....", "..^.", ...],      // 地形：'.' 草地  '^' 森林  '#' 山地

  "zones": [[-1, -1, 0, ...], ...],     // ★ 地块 → 区块 id；-1 = 不属于任何区块
  "zone_list": [
    { "id": 0, "name": "东关",
      "center": [2, 1],                          // ★ 区划中心（每个区块必须有且只有一个）
      "production": { "food": 1, "gold": 1, "population": 0.5 },   // ★ 产能：每地块每秒
      "x0": 0, "y0": 0, "x1": 3, "y1": 3,        // 最小包围盒（给渲染画底色用）
      "tile_count": 12,
      "tiles": [[0, 0], [1, 0], ...] }           // 逐个地块（冗余信息，方便人看与脚本读）
  ],
  "zone_centers": [[-1, -1, 0, ...], ...],       // ★ 地块 → 中心所属的区块 id（center 的网格写法）

  "factions": [                         // ★ 阵营表（编辑器给：id / 名字 / 颜色）
    { "id": "p1", "name": "玩家", "color": "#FFD166" },
    { "id": "p2", "name": "小明", "color": "#5AC8FF" }
  ],
  "faction_bases": {                    // ★ 各方的大本营（导出坐标系里的格坐标）
    "p1": [2, 2],                       //   每个阵营都必须有一个
    "p2": [12, 10]
  },
  "general_spawns": [...],              // ↓ 这些编辑器不管：读进来时原样留着，导出时原样写回
  "buildings": [...],
  "units": [...],
  "pvp_points": [...]
}
```

几条约定：

- **导出的是「已画地块的包围盒」**（AABB，自动算）：编辑器里的画布是无限的、内存网格还会按需生长，
  所以导出时只取你真正画过的那一片，并把坐标搬到左上角 (0,0)。
  游戏里看到的形状与相互位置完全不变，只是文件里不再有一大片「不存在」的空壳。
  一个地块都没画 → 导出成 0×0 的空地图。
  ★ **往左上画（负坐标）也一样**：包围盒是相对的，绝对坐标不影响导出的地图。
  导出前如果包围盒超过 512×512，会提醒一句「地图很大、Godot 侧要占多少内存」（**不阻止**导出）。
- **`exists` 是权威**：`0` 的格子一律不可通行（游戏里 `map_data.terrain_walkable()` 直接返回 false），
  它的 `layout` 字符是占位用的 `.`。缺这个字段 = 所有格子都存在（老地图的行为）。
- **`zones` 是权威**：`-1` 的地块不属于任何区块。缺这个字段 = 退回 6×4 均分（老地图的行为）。
- **`zone_list[].center` 是每个区块的「区划中心」**（`zone_centers` 网格是同一件事的按格写法）：
  游戏里那一格会落成一栋**中立障碍建筑**（谁都进不去、无敌、不可拆），
  点它能看这个区块的详情。**每个区块都必须有一个中心** —— 见下面第七节的硬规则。
- **`zone_list[].production` 是产能**（粮食 / 黄金 / 人口，单位 **n 资源/地块/秒**）：
  经济按「占领方拥有的各区划（产能 × 该区划地块数）」聚合。
  **只有配过非零产能的区块才写这个字段**（老图导出后仍然干净）。
- ★ **没有 `base` 字段了**（老式大本营已彻底删除）：出生点只看 `faction_bases`，
  而**每个阵营都必须有一个大本营**。手写的老图如果只有 `base`，
  编辑器**读进来时会把它迁移成 `p1` 的大本营**（那个点位本来就是主阵营的出生点），
  再导出就是新格式。游戏侧仍然能读老字段当兜底（见第五节）。
- 编辑器不碰 `general_spawns` / `buildings` / `units` / `pvp_points`（按需求：
  除了大本营，其它出生点与预置内容暂时由 Godot 侧脚本生成）——
  但**打开一张地图再导出，这几个字段会被完整带回去**，不会因为过一遍编辑器就丢了。
- `layout` 用 `.` / `^` / `#`，与 `logic/map_data.gd` 的 `LAYOUT_LEGEND` 一致。
- **文件带 BOM 也能读**（Windows 记事本 / PowerShell 存出来的 UTF-8 基本都带 BOM），
  编辑器按 `utf-8-sig` 读、按不带 BOM 的 UTF-8 写。这条不是小事：
  之前不带 BOM 就报「不是合法 JSON」，表现是「拖着地图双击启动器，窗口一闪就没」。

## 六、老地图完全兼容（这一点很重要）

用编辑器打开一张**老地图**（没有 `exists` / `zones` / `zone_centers` / `faction_bases`，
例如从别人那里手写来的图）：

- 所有格子都算存在（= 一张矩形图）
- 区块按 `config.json` 的 `zone_cols × zone_rows` **均分**，名字 A1 / A2 … / D6 —— 与 `zone.gd`
  改之前的实现**逐位一致**（id 也是同一个列优先编号）
- **每个区块会自动挑一个「区划中心」**（该区块按行优先的第一个、不在大本营上的地块）
  —— 用户要求「每个区块都必须有中心」，自动挑一个是为了让「打开旧图」不会一上来就报
  「还差 24 个中心没设」；设计者再按需要挪
- 老图里那个单数的 `base` 会**迁移**成 `p1` 的大本营（见第五节的 ★ 那一条）
- `general_spawns` / `buildings` / `units` / `pvp_points` / `_comment` 原样保留

所以「打开旧图 → 什么都不改 → 导出」得到的地图，游戏里的行为**一模一样**
（`tests/test_model.py` 里有一条断言就是钉这个的：逐行比对 `layout`、
区块网格的若干关键格、以及每个保留字段）。

一旦你在编辑器里真的划了区块 / 建了阵营，导出的图就会带上 `zones` / `zone_centers` /
`production` / `faction_bases`，`zone.build_from_map()` 与 `map_data.spawn_layout_for()`
自动切成读新字段那条路 —— 不需要改代码、不需要开关。

> ⚠️ **随游戏发布的那张图已经搬到新格式**（只剩 `data/test_map.json`；老图 `map_01.json`
> 已按用户要求删掉）：27×22、594 个地块、14 个区块（a1…g2）都有自己的中心与产能，并带
> `faction_bases: {"p1": [7, 2], "p2": [19, 19]}`。
> 上面说的「老地图」兼容路径现在是给**手写 / 外部旧图**留的，不再是发布图的状态。
>
> ⚠️ 那张图是**设计师在编辑器里随时会改**的东西：加了地块 / 加了区块之后，
> Godot 侧那些「写死坐标或数量」的断言会成片红（这一轮加 f/g 四个区块时红了 14 条）。
> 所以两侧的测试都尽量用「地图自己说的数」断言，只有 `test_smoke.gd` 的
> `EXPECTED_MAP_*` 是**故意写死**的（它要能抓住「图被换掉了」这件事）。

## 七、导出前的两条硬规则（不是提醒，是拦住）

`do_export()` 先过 `MapModel.blockers()`；**有问题就弹错误框、一个文件都不写**：

| 规则 | 为什么 |
|---|---|
| **每个阵营恰好一个**大本营 | 游戏里「一方一座大本营」；缺了那一方就没有基地 |
| **每个区块恰好一个**区划中心 | 用户原话「设计师需要确保每个区块都有一个区划中心」 |

「多了」在数据层不可能：`faction_bases` 是 `阵营 → 一格` 的字典、`Zone.center` 只有一个值，
所以只查「少了」。

与「提醒」的分工（别混起来）：

| | 返回 | 表现 |
|---|---|---|
| `problems()` | 提醒 | 「导出去能跑，但多半不是你要的」→ 弹确认框，**确认后照导** |
| `blockers()` | 拦住 | 「这份地图不合法」→ 弹错误框，**什么都不写** |

提醒里有：地图上一个地块都没有、有区块没地块、中心落在山上 / 与大本营叠格、
大本营落在山上、阵营 id 游戏不认识、地图特别大（> 512×512）。

```
├── __main__.py     入口（命令行参数 / --selftest）

│                   两条硬规则（blockers）、撤销快照（**不依赖 tkinter**，可无头测试）
├── mapfile.py      地图 JSON 的读写（Godot 格式、旧地图兼容与 base 迁移、字段保留、带 BOM 也能读）
├── app.py          tkinter 界面（画布、侧边栏、三个页签、工具栏的导入导出按钮、框选、快捷键）
├── test_model.py   数据层无头测试（252 项）
├── test_app.py     界面动作无头测试（341 项：含阵营 / 区划中心 / 产能 / 导出硬拦截 /
│                   框选（含「焦点跑掉」那条） / 跟手度 / 缩小不卡 / 页签来回切不死循环）
├── bench_app.py    跟手度基准：一个鼠标事件（回调→重绘→画到屏上）要多少毫秒
└── README.md       本文件
```

分层是刻意的：**格式与规则全在 `model.py` / `mapfile.py` 里**，界面只负责把点击翻译成对模型的操作。
所以「导出的地图游戏能不能读」这件事可以在没有窗口的情况下测（`test_model.py` 就是干这个的），
这也是仓库里 `logic/` ↔ `view/` 那条老规矩的小号翻版。

### 改这个界面之前值得知道的坑（都实测踩过）

1. **`canvas.winfo_width()` 在窗口映射之前是 1**：构造 `EditorApp` 时窗口还没显示，
   那时算初始缩放/居中是错的（症状：格子大小与位置都不对）。所以初始视野推迟到
   `apply_initial_view()`（由 `<Configure>` 触发）里做。
2. **`create_line` 传超过 2 个点会画折线**：原来那批「顶点小点」每点 4 个坐标，
   被连成了一串**斜线**（用户报的「斜着的线」就是这么来的）。要画点就用 `create_oval`，
   或者每次只传 2 个坐标。
3. **tk 的按钮点过之后会拿住键盘焦点**，而**空格在 tk 里是「激活焦点按钮」**：
   于是「按住空格拖画面」会变成「反复点最后按过的那个页签」——用户看到的就是
   「点页签有时没反应 / 页面乱跳」。修法：所有按钮走 `_button()`（`takefocus=0` + 点完把焦点交还画布）。
4. **Canvas 的 item id 在 `delete("all")` 之后作废**：重画后再用旧 id 会读到别的图元。
5. **`_left_down_at` 这类状态用完必须清掉**：不然「按下—抬起」没配对时，
   下一次点击会被当成拖动而**静默忽略**（症状：有些格点一下没反应）。
6. **窗口太小/未映射时 `screen_to_tile` 仍然会给格子**（画布无限），
   但点出来的位置会落在视野外 —— 写测试时别把「窗口尺寸」和「落点」混起来断言。
7. **重绘与控件重建都别放在高频路径上**：合并重绘（`request_redraw`）、
   `HOVER_THROTTLE_MS`、`BIG_CELL_PX`、`MIN_GRID_PX`、以及「就地改值」的
   `refresh_tile_panel()` / `refresh_zone_panel()`。少一个立刻能感觉到（数字见第十节）。
8. **测试里 `after` 要等真实时间**：`root.update()` 只处理待办事件、不推进定时器，
   验证「攒着的那次重绘补上了」必须 `time.sleep` 一下再 `update`。
9. **`withdraw()` 之后 canvas 是 1×1**：要在窗口还映射着的时候 `new EditorApp`，
   否则初始视野按 1×1 算，所有屏幕↔格换算的断言都会静默偏掉（测试 `build_editor` 就是这个顺序）。
10. **★★ tk 的 Treeview 在「新建 / 销毁」时就会派发 `<<TreeviewSelect>>`**：
    「点页签 → 重建侧边栏 → 新建 Treeview → 触发选区事件 → 又重建侧边栏」会**无限递归**，
    表现就是「点完地块再点区块，程序无响应」（实测必现，一开始还以为是卡慢）。
    所以 `refresh_sidebar()` 有重入闸 `_rebuilding`，`on_zone_select()` 还会在
    「选中的没变」时直接返回。**视图控件的生命周期事件不能当成用户操作** ——
    详见 `docs/pitfalls.md` 5.23。
11. **★★ 能「就地改值」就别重建控件**：整条侧边栏重建要 **18~31 ms**（20 来个控件销毁+重排），
    区块页更贵（要重 new 一个 24 行 Treeview，**300+ ms**），而就地改几个
    label/button 只要 **~4 ms**。这条是「点一下地感觉卡」的根因，详见 `docs/pitfalls.md` 5.24。
12. **★ 面板的结构判断只能有一处**：`refresh_tile_panel()` 里那个
    「这一格存不存在变了就转 `refresh_sidebar()`」的闸门，一开始我放在**调用方**
    （点格子时判断），结果「右键删格 / 撤销 / 导入」都会绕过它，
    留下一个「按钮看着还能点、点下去没反应」的旧面板（测试当场抓住）。
    **同一个不变量只在一个地方判**。
13. **★ 别用 `Get-Content` / `Set-Content` 改这个目录里的文件**：本文件曾经被
    `(Get-Content -Raw) -replace ... | Set-Content` 毁过一次 —— PowerShell 5.1 的
    `Get-Content` 默认按**系统代码页**（中文 Windows 是 cp936）解码，
    于是 UTF-8 的中文被当成 GBK 读进来，一趟来回就丢了 448 个字节组，中文全变乱码。
    改文本文件请用编辑器的读写工具，或者显式 `-Encoding UTF8`。
14. **★ 框选走的是 `event.state` 的 Shift 位，不是 keysym**：鼠标事件里没有
    `keysym`，写测试造事件时忘了给 `state`，编辑器就会把「Shift + 拖拽」当成普通拖拽
    （静默不框选）。`test_app.fake_mouse(shift=True)` 是唯一该用的造事件入口。
15. **★ 阵营 id 不做数字映射、也不做合法性校验**：id 就是 Godot 的阵营字符串，
    导出的 `faction_bases` 以它为键。写错 id 不崩、也不阻止导出，只在导出前提醒一句
    —— 把别人手写地图里的阵营悄悄吃掉，比留着它更糟。
16. **★★ tk 的鼠标事件不保证带修饰键位**：实测 `<ButtonPress-1>` 的 `state` 是 `0x0`
    （Shift 没跟过来），拖动期间也可能发带 B1 位的 `<Motion>` 而不是 `<B1-Motion>`。
    所以「按住 Shift 拖拽」必须**同时**从键盘事件跟踪 Shift，并且把拖动分派放到
    `on_motion` 里按 `state` 的 B1 位走 —— 只靠 `<B1-Motion>` 与 `state & Shift`
    会**静默失效**（用户报过一次：框选完全没反应）。详见 `docs/pitfalls.md` 5.26。
17. **★★ 键盘事件只送给「有焦点的那个控件」**：接着上一条 —— Shift 只绑在画布上还是不够。
    侧边栏的按钮 / 下拉框 / 区块树被点过之后，焦点就留在那边了（`takefocus=0` 只挡 Tab，
    挡不住鼠标点击拿焦点），画布上的 Shift 绑定**根本不响**；再赶上鼠标事件不带 Shift 位，
    框选又变成静默失效（用户第二次报的就是这条）。**绑到 root + canvas 两处**才稳。
    ⚠️ 验证方式：走真实事件（`event_generate`）**并先把焦点摆到侧边栏上**；
    直接调 `editor.on_shift_down()` 测不出这类 bug（见 `docs/pitfalls.md` 5.32）。
18. **★ 警告也要跟着语义改**：`problems()` 里那句「大本营点位没设」在有了阵营大本营之后
    就**不再是「没设出生点」**，而只是「某个没设大本营的阵营会用到它」。
    没跟着改的后果是用户被一句不该出现的警告带着去改本来没问题的东西。
    **改了数据模型，就要回头把每一条校验的语义重读一遍。**

## 十、还没做的（有意不做）

| 不做 | 说明 |
|---|---|
| 预置建筑 / 预置单位 / 将领出生点 / 多方起点轮换 | 按需求：编辑器只管地形、区块（含**区划中心**与**产能**）、各阵营的大本营；其余由 Godot 侧脚本生成。字段本身会原样带过去 |
| 撤销栈落盘 | 导出即保存，`Ctrl+Z` 只在本次会话里有效 |
| 地形笔刷（按住拖动批量刷） | 按需求：**没有笔刷**。单格改地形在属性面板里选，成批改就用 `Shift` 框选（见第四节第 5 小节） |
| 「地图尺寸 / 铺满这个范围 / 裁剪到画布」 | 按需求：设计时不用考虑尺寸，导出范围永远是已画地块的包围盒（见第三节末尾的说明） |
| 区块涂刷 | 区块是**逐格点选**（再点一次取消），一次一格；成批划归用框选 |
| 框选里批量**创建**地块 | 按需求：虚线格不参与框选（框选是「改已有的地」，不是「批量画地」） |
| 多选 / 框选 / 复制粘贴 | 框选已经有了（见第四节第 5 小节）；复制粘贴用不上 |
| 每个阵营多个大本营 / 初始领地 | 按需求：一个阵营**一个**大本营（对齐 Godot 的 `TYPE_BASE`：一方一座基地），而且**必须有**（导出前拦住） |
| 每个区块多个区划中心 | 同上：一个区块**一个**中心（它落成一栋占格的中立障碍建筑，多了会互相挡路） |
| **真·无限画布（稀疏存储）** | 内存网格是稠密数组（`cols×rows`），所以坐标上限是 `±4096`（约 1600 万格 / 150 MB）。要真正无上限得把 `existing`/`terrain` 换成只存「画过的格子」的 dict —— 那是一次数据层重写（`model.py` / `mapfile.py` / 两层测试都要动），与「地图尺寸」这件事无关，要做请单独一轮 |
| 地形美术 | 编辑器用 `config.json` 里的配色画色块；真美术在 Godot 侧 |
| 自动检查地图可玩性 | 「**拦住**」两条：每个阵营有大本营、每个区块有中心；「**提醒**」几条：没地块 / 空区块 / 中心在山上或与大本营叠格 / 大本营在山上 / 阵营 id 不认识 / 地图特别大 |

## 十一、跟手度：实测数字与「别做什么」

这一节是「为什么它拖起来跟手」的账本。数字由 `bench_app.py` 量出来
（1280×800 窗口，一次事件 = 回调 → 重绘 → `update_idletasks()` 把图画到屏上）。
判据是**一帧 16.7 ms**：超过它的操作都会被人眼看成「顿」。

### 改这一版时量到的账

| 操作 | 改之前 | 改之后 | 为什么 |
|---|---|---|---|
| 左键点一下建一格 | **18~31 ms**（最坏 48 ms） | **~5 ms** | 原来每点一下把整条侧边栏销毁重建（20 来个控件）；现在能就地改值就就地改值 |
| 划过一格的重绘节流 | 40 ms | **16 ms** | 一次重绘只要 3~5 ms，节流定成 40 ms 就是白让高亮落后光标两帧半 |
| 区块页：划一格 / 换选中项 / 改名字 | 每次重建侧边栏（每页 300+ ms，因为要重 new 一个 24 行 Treeview） | **不重建**（只改那一行 / 图例 / 详情） | 行数没变就不需要重建列表 |
| 点自己已经选中的页签 | 白重建一遍 | **直接返回** | 「点了必须有反应」不等于「点了就得重建」 |
| 测试里「地块 ↔ 区块 来回切 3 轮」 | 3.5~5.3 s（偶发超过 5 s 阈值） | **2.1 s** | 上面两条一起省下来的 |

### 现在的数字（一次事件从回调到画完）

| 场景 | 平均 | 最坏 |
|---|---|---|
| 空画布重绘（721 图元） | 5.6 ms | 5.7 ms |
| 64×64 画满地：悬停划格 | 3.6 ms | 4.0 ms |
| 64×64 画满地：拖动一帧 | 3.5 ms | 4.1 ms |
| 64×64 画满地：滚轮缩放一次 | 3.2 ms | 3.9 ms |
| 点一下建一格（含属性面板） | 4.9 ms | 9.0 ms |
| 在面板里改地形 | 5.0 ms | 5.8 ms |
| 0.35 倍视野重绘（155 图元） | 2.7 ms | 2.8 ms |
| **区块页**：24×16 全部划入 24 个区块（真实规模，1489 图元） | **6.0 ms** | — |
| **区块页**：64×64 全部划入 256 个 4×4 区块（压力测试，2137 图元） | **16.7 ms** | — |

结论：**画布这一层的重绘本来就够快（3~7 ms）**，真正的瓶颈是「点一下就把控件全重建一遍」。
所以优化跟手度的顺序是：先别重建控件 → 再把节流调回一帧 → 最后才是重绘本身。

> **区块页那 16.7 ms 的账**（已知的性能上限，压力测试才到得了）：一屏里 2137 个图元 ——
> 720 个区块底色、720 个虚线格、约 700 条边界线。它贴着 60fps 的边，
> 而现实里的地图是 24 个区块（6 ms）。要再快就得动「区块底色/边界怎么画」
> （比如把同色的边界线合成一条 `create_line`、把底色按连通块合成多边形）——
> 那属于渲染层的重构，**改之前请先跑 `bench_app.py` 拿到数字**，别凭感觉动。

### 基准程序本身踩过的两个坑

- **`canvas.update_idletasks()` 必须算进计时**：tk 是攒着画图命令一起下发的，
  只调 `redraw()` 量到的是「把命令排进队列」的时间，不是「画完」的时间（差着一倍）。
- **FakeEvent 必须带 `.delta`**：真实鼠标事件有它，基准里漏了的话 `on_wheel` 会半路抛异常，
  量出来的数字全是假的（而且看起来「很快」）。
