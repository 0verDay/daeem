# DAEEM 单位编辑器

改**游戏数值**的工具：单位（兵种）/ 将领 / 建筑 / **单位特性 / 将领特性**。
★ 2026.11：**科技不在这里改** —— 科技的两张表（`tech.list` /
  `tech.clan_list`）、每派 9 个槽位、以及「最多同时启用几条 / 每阶每秒扣金」
  全在 `tools/tech_editor` 里（见那个工具的 README）。
★ 2026.11：**特性拆成两张池 + 两个独立页签**（用户口径：「把所有单位特性与将领特性
  打包为单独的标签；将领特性仅适用于将领，单位特性仅适用于单位」）：
  「单位特性」页定义兵种可挂的标签，「将领特性」页定义将领可挂的光环标签，
  「单位」页只负责给具体兵种 / 将领**挂哪几条**。
它写的文件是 `daeem/data/config.json` —— 也就是 `logic/config.gd` 读的那一份
（**唯一**的一份数值表）。地图编辑器（`tools/map_editor/`）改的是
`daeem/data/maps/<id>/map.json`（一个地图一个目录），两个工具各管一头，互不重叠。

Python + tkinter，**零第三方依赖**，与地图编辑器同一套界面风格与启动习惯。

## 一、怎么打开

| 方式 | 命令 |
|---|---|
| **双击**（设计师用这个） | `dev_gd_a/tools/unit_editor/unit_editor.bat` |
| 命令行 | `python dev_gd_a/tools/unit_editor` |
| 改另一份配置（对照 / 试验） | `python dev_gd_a/tools/unit_editor 别的配置.json` |
| 拖一份 json 到 bat 上 | 同上（拖进去的那一份） |
| 不开窗口，自检一遍 | `python dev_gd_a/tools/unit_editor --selftest` |

`--selftest` 会把「游戏真的会读的那些数」逐条打印出来（单位 / 将领 / 建筑含每级），
并验一遍「改一处写回 → 改回来与原文逐字节一致」。怀疑两边漂了就先跑它。

> ★ 为什么没有「打开文件」这个动作：单位数值**只有这一份**，打开编辑器就是为了改它。
>   地图编辑器要打开不同的地图，所以那边有导入 / 导出；这边默认直接落在
>   `<工程>/data/config.json`，「另存为」留着做对照。

## 二、界面

```
┌──────────────────────────────────────────────────────┬──────────────┐
│ [单位] [单位特性] [将领特性] [建筑]  保存 重载 另存为 │   侧边栏      │
├──────────────────────────────────────────────────────┤  选中条目的   │
│  兵种列表 / 组合招募单 / 将领列表（「单位」页）        │  全部数值     │
│  单位特性池（骑兵特攻 / 远程抵抗 / 稳定…，可增删）     │              │
│  将领特性池（神速 / 近战抵抗 / 横扫…，可增删）         │              │
│  ＋ 新建兵种…  删除兵种  ＋ 新建将领…                 │              │
├──────────────────────────────────────────────────────┤              │
│ 状态栏：文件路径 · 改没改 · 上一次操作的结果            │              │
└──────────────────────────────────────────────────────┴──────────────┘
```

| 页签 | 左边是什么 | 右边能改什么 |
|---|---|---|
| **单位** | 兵种（可增删）+ **组合招募单**（协防军 / 御林军）+ 将领名册（**可加**） | 兵种：归属（步兵 / 骑兵）/ 远程 / 名称 / **地图上的字** / 血量 / 攻击力 / 攻击距离 / 攻击速度 / 移动速度 / 身体半径 / **视野半径** / **造价（粮食·黄金·人口）**（派系兵种自动落到 `clan.list[].recruit[]`）/ **特性（可挂多条「单位特性」标签）**；组合招募单：名字 / 方框字 / 说明 / **整包造价**（一次出 2~3 人那一单）；将领：**阶（0~3）** / **派系归属（原生·王朝·帝国，可多选）** / 类型 / 名字 / **编制上限** / **招兵读条** / **自己的一套数值（血量·攻击力·距离·攻速·移速·视野）** / **将领特性（可带多条，每条只做一件事）** / **成长（仅 0 阶：每级血量·攻击）** / 造价 |
| **单位特性** | 单位特性池（可增删；迁移后 13 条） | 一条特性的**名字 / 短名 / 说明 / 效果**：对某大类伤害 +x% · 近战减伤 · 远程减伤 · 免疫击退。**只作用于单位**（将领按所属兵种继承） |
| **将领特性** | 将领特性池（可增删；现在 13 条） | 一条特性的名字 / 短名 / 说明 / **光环效果**（移速·攻速 / 远近减伤 / 对某大类伤害 / 稳定 / 占领速度 / 招募折扣 / 冲锋加成 / 横扫）。**只作用于将领本人 + 旗下部队** |
| **建筑** | 三种建筑 + 设计师新加的（可增删） | 名称 / 说明 / 快捷键 / 可建造 / **建造时间** / 造价（粮食·黄金）/ 血量 / 本体大小 / **视野半径** / **可攻击**（勾上才显示攻击力·距离·攻速）/**升级表每一级**（需要的价格·读条时间·血量倍率 ⇒ 换算成血量）+ 每一级的攻击三属性 |
| ~~科技~~ | ★ 2026.11 **页签已移除**：科技改在 `tools/tech_editor` | —— |

操作习惯：

* 输入框里改完 **按 Enter**（或点别处）生效；**打错字不会写坏数据**，状态栏会说一句「要填数字」。
* **Ctrl+S** 保存 · **Ctrl+Z / Ctrl+Y** 撤销 / 重做 · **F5** 从磁盘重读。
* 数字超出合理范围会被**夹住**（血量 ≥ 1、本体大小 0.05~1.0 等），状态栏会说明夹到了多少。
* 顶栏那个 `● 未保存` 表示有改动还没写回文件。
* **右侧面板装得下时不能滚**（滚动条滑块铺满 = 固定住）：内容比面板短的时候上下滚
  不会把表单推走、也不会在上方/下方露空白；只有真的装不下才滚，而且滚不到范围外
  （Tk 在「内容比视口矮」时照样允许滚，这是个坑，见 `docs/pitfalls.md` 5.55）。
* **界面主题**：浅色（白）+ 极简的一整套（页面底 / 卡片面 / 输入面三层灰 + 一条冷色强调色），
  按钮是**圆角**的（`RButton`）。两个坑的修法在 `app.py` 里，改之前先看：
  * **下拉框选中后不能变白**：clam 主题在 `readonly` 状态下会把下拉框的底落回浅灰
    （实测 `dcdad5`），光 `style.configure` 压不住 —— 必须 `style.map` 把
    `readonly` / `active` / `disabled` 这几个状态一起按下去（见 `_apply_theme`）。
  * **改一个数值不再闪白**：整块重建控件时用 `WM_SETREDRAW` 关绘制、建完再打开并
    `RedrawWindow`（`_NoRepaint`）。⚠️ 别改回 `LockWindowUpdate`：DWM 下压不住
    Tk 销毁/新建控件的中间态。
  * **改数值不重置滚动/选中**：`refresh_all()` 重建前拍快照、重建后恢复侧边栏滚动、
    列表滚动与键盘焦点；只有换页签 / 换选中项才回顶部（`_sidebar_reset_pending`）。
    ★ 重建列表时 `selection_set()` 延迟派发的 `<<TreeviewSelect>>` 也要按「回声」忽略，
    否则会再重建一次侧边栏并把滚动位置打回 0。

## 三、每个字段落在 config.json 的哪一行

游戏侧读的就是这些键（`logic/config.gd` / `building.gd` / `unit.gd` / `combat.gd`），
**改名字要两边一起改** —— `tests/test_unit_editor.gd` 与 `test_model.py` 第 [6] 节
把这份契约钉成了断言（一边改了另一边没跟上，测试会红）。

### 单位（页签「单位」）

| 界面上的字段 | config.json 里的位置 |
|---|---|
| 归属（步兵 / 骑兵） | `unit.types.<id>.class`（`infantry` / `cavalry`，可选值来自 `unit.classes`） |
| 远程 | `unit.types.<id>.ranged` |
| 名称 | `unit.types.<id>.name`（**同时**写 `recruit.list[].label`，两处不一致看着像 bug） |
| 血量 / 攻击力 / 攻击距离 / 攻击速度 / 移动速度 / 身体半径 | `unit.types.<id>.hp_max` / `damage` / `range` / `cooldown_sec` / `speed` / `radius_factor` |
| **地图上的字** | `unit.types.<id>.icon` —— **正好一个字符**，地图上那个单位就画这一个字（深色字压在**阵营色圆盘底**上；将领的圆盘描边更粗）。**不写这个键** = 跟着**名字的第一个字**（长枪兵 → 长）。内置四种写着 枪 / 弓 / 骑 / 敌 |
| **视野半径** | `unit.types.<id>.vision`（**格**）—— 战争迷雾里这个单位能看多远（从它所在的**格心**算起，视线被**山脉**挡住，其他地形不挡）。**清空输入框 = 删掉这个键** → 回到 `fog.vision_default`（默认 8）。想改全局兜底就手改 config 的 `fog` 段；建筑的视野是 `fog.vision_building`（建筑没有类型数值表，本轮共用一个数） |
| **冲锋**（2026.11） | `unit.types.<id>.charge.<键>` —— 近战兵种的被动冲锋：`min_distance`（连续直行多少格进入冲锋态）/ `max_distance` / `turn_max_deg`（与起始方向的最大夹角）/ `speed_bonus` / `damage_bonus` / `knock_distance` / `knock_stun_sec` / `splash_radius` / `splash_damage_ratio` / `cooldown_sec`。**不写 / `min_distance = 0` = 不冲锋**；清空某一项 = 删掉那个键（读回 0）。远程骑兵即使写了也不冲锋 |
| 造价（粮食 / 黄金 / 人口） | `recruit.list[kind = <id>].cost.food` / `.cost.gold` / `.population_cost`（派系兵种在 `clan.list[].recruit[kind = <id>]`，工具会自动写对位置） |
| 命令卡名字 / 方框字 / 说明 | `recruit.list[kind = <id>].label` / `.short` / `.desc`（同上：按条目实际所在的表写） |
| **持久消耗 — 每秒耗粮**（2026.11.4） | `unit.types.<id>.upkeep_food`（**粮/秒**）。每个**存活**单位每秒吃这么多粮（`world._tick_upkeep()` 按存活单位累加）。**清空输入框 = 删掉这个键** → 跟随下面那一行「大类默认」 |
| **持久消耗 — 大类默认** | `unit.classes.<class>.upkeep_food` —— 同大类里**没单独写**的兵种都跟它。改它会影响这一类里所有没覆盖的兵种（界面上那一行的标签会写明是哪一类，例如「步兵 默认」） |

**攻击速度**填的是**两次攻击之间的间隔秒数**（越小越快）—— 数据里就叫 `cooldown_sec`。

★★ 2026.11.2：**「招募时间」这一栏已从单位页移除** —— 读条不再属于兵种。
单位页的读条 = **招它的那位将领**的属性（`unit.general.recruit_sec[i]`，默认 10 秒），
见下面将领表里的「招兵读条」。队列长短、队列里是什么兵种都**不影响**它。

★★ 2026.11：**派系专属兵种**（王朝 `dy_*` / 帝国 `dg_*`）的招募条目在
`clan.list[].recruit[]`（见 `data/config.json` 的 `clan` 段）。本工具**已能读写那一张表**：
选中它们之后，「造价 / 命令卡文案」改的就是 `clan` 里那一条（悬停标题会写明来源，
例如 `clan:dynasty`）。⚠️ **不要**为了改它们的价钱就把它们加进 `recruit.list`：
那会让它们变成**所有派系都能招**。

★ 组合单位的**零件**（协防军枪 / 弓、御林军剑盾 / 弓 / 着甲骑）没有自己的招募条目 ——
它们是某一单（「协防军」/「御林军」）里 `spawn` 出来的。本工具会把它们的造价列显示成
「随「协防军」」、详情页说明「由某一单整包生成」，**不会**再谎报「不在招募表」，
也不给一组改不动的输入框（造价在那一单上，去改那一单）。

### 单位特性（页签「单位特性」= 池；「单位」页 → 选中兵种 →「特性（可多条）」= 挂哪几条）

★★ 2026.11：兵种特性改成**标签制**（用户口径：「把所有单位特性打包为单独的标签；
单位特性仅适用于单位」）。两层的分工固定：

* **单位特性池**（`unit.unit_traits.<id>`）定义「一条特性是什么」：名字 / 短名 / 说明
  + **一个**效果；
* **兵种**（`unit.types.<id>.trait_ids`）只记「我挂哪几条」—— 一个兵种可以挂多条。
* 将领按**所属兵种**继承这些标签（`unit.create` 抄到单位身上），所以将领表单里没有
  第二份单位特性输入框 —— 想给将领**单独**加强，用下面的「将领特性」。

| 界面上的字段 | config.json 里的位置 |
|---|---|
| 特性池：名字 / 短名 / 说明 | `unit.unit_traits.<id>.name` / `.short` / `.desc` |
| 特性池：**对某大类伤害**（一行一个大类，可加可删；0.25 = +25%） | `unit.unit_traits.<id>.attack_vs_class.<大类 id>` —— 大类 id 来自 `unit.classes`（步兵 `infantry` / 骑兵 `cavalry` / 器械 `siege`）。只对**单位**生效，拆建筑不受影响 |
| 特性池：**近战减伤** | `unit.unit_traits.<id>.melee_reduction`（0~1；0.25 = 少受 25%） |
| 特性池：**远程减伤** | `unit.unit_traits.<id>.ranged_reduction`（0~1；只挡投掷物 / 箭） |
| 特性池：**免疫击退（稳定）** | `unit.unit_traits.<id>.knockback_immune`（`true` = 免疫击退位移 + 眩晕；碰撞挤开照旧） |
| **兵种挂哪几条** | `unit.types.<id>.trait_ids`（**数组**；`[]` / 没写 = 没有特性） |

* ★ 一条特性 = 一个特性名 = 一个效果（与将领特性同一条口径）：一条只写**一个**效果键。
* 减伤与加成写的都是**比例**（`0.25`），不是百分数；界面上「加一条」的缺省是 **0.25**。
* **清空输入框 = 删掉那个键**（游戏侧读回 0 / false）；摘掉兵种最后一条标签时
  `trait_ids` 整个键也删掉（文件里不留 `[]`）。
* 改池里一个**已有**的值只动一行（`test_model.py` 钉着 1 行 diff）；加 / 删键会重排
  那一小块（`configfile` 往多行字典尾部插键时缩进按「最后那个子项的值」算，所以整块重写）。
* **删掉一条正在被挂的特性**时，所有挂着它的兵种会被自动摘掉
  （`test_model.py` / `test_app.py` 都钉着「不留指向空 id 的记录」）。
* **兼容老写法**：`unit.types.<id>.traits`（内嵌四键）游戏侧**仍然会合并**
  （`config.gd` 的 `unit_traits_of()`：inline ⊕ 标签），但编辑器不再写它；
  迁移时已经把现有兵种全部换成标签了。若某个兵种还留着老键，兵种表单会多一行
  ⚠ 灰字提示，告诉你「它也会生效、但本工具不编辑」。

### 将领特性（页签「将领特性」= 池；「单位」页 → 选中将领 →「特性（可多条）」= 挂哪几条）

★★ 2026.11.3 新增、2026.11 起独立成一页（用户口径：「将领特性仅适用于将领」）。
这里同样是**两张表**：

| 界面上的字段 | config.json 里的位置 |
|---|---|
| 特性池：名字 / 短名 / 说明 | `unit.general_traits.<id>.name` / `.short` / `.desc` |
| 特性池：移速加成 / 攻速加成 | `unit.general_traits.<id>.speed_bonus` / `.attack_speed_bonus`（比例；攻速 +0.25 = 攻击间隔 ÷1.25） |
| 特性池：近战减伤 / 远程减伤 | `unit.general_traits.<id>.melee_reduction` / `.ranged_reduction`（0~1） |
| 特性池：对某大类伤害 | `unit.general_traits.<id>.attack_vs_class.<大类 id>` |
| 特性池：**稳定**（2026.11） | `unit.general_traits.<id>.knockback_immune`（`true` / 删键） |
| 特性池：**占领速度加成**（2026.11） | `unit.general_traits.<id>.capture_speed_bonus`（比例，0.4 = +40%；只在这个光环的单位站在区划中心邻域时生效） |
| 特性池：**招募骑兵折扣**（2026.11） | `unit.general_traits.<id>.recruit_cavalry_discount`（0~1，0.25 = 骑兵招募 -25% 资源） |
| 特性池：**近战骑兵冲锋加成**（2026.11） | `unit.general_traits.<id>.charge_damage_bonus`（比例，1.0 = 冲锋额外伤害 +100%） |
| 特性池：**横扫**（2026.11，只读） | `unit.general_traits.<id>.melee_splash`（`{radius, knockback, stun_sec}`：攻击附带范围伤害 + 击退） |
| **这位将领带哪几条** | `unit.general.trait_ids[i]`（与 `unit.general.types` 同序；**数组**，`[]` = 「无」） |

* ★★ 2026.11：**一个特性 = 一个特性名 = 一个效果**（用户口径：不存在「一条特性里塞好几个
  不相干效果」）。所以一条特性只写**一个**效果键；「阿吉诃德」的两条是「一呼百应」（招募骑兵
  -25%）与「新骑士精神」（冲锋额外伤害 +100%），「稳定」的效果就是「免疫击退」。
  「横扫」是「攻击附带范围伤害 + 击退」这一件事（`melee_splash` 一个键），子刹带的它
  对**本人 + 旗下部队**生效；编辑器里只读显示，改它要去 `config.json`。
* ★★ **一位将领可以带多条特性**：将领表单里是「一行一条 + 末尾加一条」，可加可删；
  `unit.general.trait_ids[i]` 是**数组**（老配置写成字符串也认 = 只有一条）。
  多条同时生效时：比例类**相加**、免疫类取「或」、占领 / 招募折扣取最大。
* 特性是**全局一份池**（一族效果的定义），将领只是「点名要池里的哪几条」；
  「＋ 新建将领特性…」照一条模板复制（效果照抄，**短名不抄** —— 删掉就跟着名字首字）。
* **删掉一条正在被使用的特性**时，用它的那位将领会被自动摘掉。
  只删池里那份、留着 `trait_ids` 里的 id，会让游戏读到一条永远匹配不上的特性 ——
  那是本项目最贵的一类 bug（`test_model.py` / `test_app.py` 都钉着这一条）。
* ★★ **生效范围**：将领**本人 + 旗下所有单位**（附属兵出生时继承同一条光环，
  见 `world.fill_general_retinue` / `_spawn_from_recruit`）。区划招募出来的将领也按
  `trait_ids` 授予。
* ★ 默认配置里 `trait_ids` 全是空数组（除设计师点过名的那几位），所以这个功能加进来
  **没有改变任何既有数值**。2026.10 停用的「随机抽词条」不再回来 ——
  现在没有随机，只有配置指定。

### 组合招募单（单位页 → 左下「组合招募单」那一栏）

★ 这一栏是给**不是兵种**的招募条目用的：它们的 `kind` 不在 `unit.types` 里，
一次下单靠 `spawn` 生成好几个单位 —— 现在有两条：

| 招募单 | kind | 一次出 | 整包造价 |
|---|---|---|---|
| 协防军 | `dy_guard` | 枪 + 弓（2 人） | 145 粮 / 0 金 / 2 人口 |
| 御林军 | `dy_royal` | 剑盾 + 弓 + 着甲骑（3 人） | 195 粮 / 300 金 / 3 人口 |

| 界面上的字段 | config.json 里的位置 |
|---|---|
| 名字 / 命令卡方框字 / 说明 | `clan.list[].recruit[kind = <kind>].label` / `.short` / `.desc` |

| 组成（只读） | `clan.list[].recruit[kind = <kind>].spawn[]` |

★ 成员自己的血量 / 攻击 / 素材仍然去**兵种**列表里改（它们各自有 `unit.types.<id>`）；
★ 读条时长不在这里（也不在那一单上）：由**招它的将领**的 `unit.general.recruit_sec` 决定。
★ 判据是「`kind` 在不在 `unit.types` 里」而不是「有没有 spawn」—— 将来若出现
「一单只出一个非兵种单位」，它也会自动出现在这一栏，不必改代码。

## 四、写入策略：**只动改过的那几个字符**

`configfile.py` 不整份重排 JSON，而是「按字符区间做一次拼接」：

* 没改就保存 → **逐字节等于原文件**（有断言钉着）；
* 改一个数字 → 全文件**只有那一行**变化（实测：`"hp_max": 160` → `175` 就一处 diff）；
* 改回原值 → 文本**逐字节回到原样**；
* 新增条目 → **照一个模板复制原文**（连排版一起抄），所以新兵种 / 新建筑与邻居长得一样。

为什么不 `json.dump` 整份重写：这份文件是**手写 + 带注释**的（那些 `"_comment"` 就是文档），
而且很多条目刻意压在一行里。实测整份重排会让 **898 行里约 320 行**变化 ——
设计师改一个数字，diff 里躺着三百行格式噪音，`git blame` / review / 回滚全废。

> ★ **尾逗号**：Godot 的 JSON 解析器容忍尾逗号，Python 的 `json` 不容忍。
>   编辑器**读**的时候容忍（不跟它计较），**写**出来的永远是严格合法的 JSON ——
>   于是「手改 config.json 时多打了一个逗号」会在第一次保存时被顺手治好。
>   （仓库里那个尾逗号本轮已经清掉了。）

## 五、新建 / 删除的规矩

* **新建兵种**：填 id（英文小写 + 下划线）、名字，再选一个模板照抄 ——
  连招募表那一项一起建出来（模板不在招募表里就照默认值建）。新单位**不抄模板那个字**：
  地图上先跟着它**名字的第一个字**（「马弓手」→ 马），想换就在「地图上的字」里填一个字。
* **新建建筑**：同样照模板复制，并且强制 `buildable = true`
  （否则它在游戏里根本出不来，设计师会以为编辑器坏了）。
  ★ 2026.10.26 起**不再自动配升级表**（只有大本营可以升级）。
* **删除**：只能删**设计师自己加的**。内置的那几个（长枪兵 / 长弓兵 / 骑手、
  木墙 / 哨塔 / 石墙 / 警戒塔 / 大本营）**不许删** —— 代码与测试按 id 引用它们，删掉不会报错，
  只会让游戏在某条路上静默走兜底值（这个项目最贵的一类 bug）。
  删兵种时，正在用它的将领会被改成第一个还存在的兵种。
  ★ 历史：「测试敌人」（enemy）曾是内置单位之一，已随游戏侧的删除一起从编辑器移除。
* **加将领**（2026.11.5）：「＋ 新建将领…」填 **名字 / 模板兵种 / 阶**，追加在名册**末尾**
  （开局将领 #0 固定第 10 档）。它只进 `unit.general.*` 那几张同序表，
  **不写 `recruit.zone.list`** ⇒ 不会被区划招出来（用户拍板：「只加数值档，不进招募九宫格」）。
  ★★ 2026.11：选的那个兵种只是**模板** —— 会先复制出一条**只属于这位将领**的独立兵种
  （`unit.types.<模板>_lord_<序号>`，名字 / 图标取将领名）再让 `types[i]` 指向它。
  用户口径：「将领应当是单独的单位，有独立的对象……后续要加新将领也独立」；
  改这位将领的数值 = 改它自己的兵种，不会连带改到模板 / 别的将领。
  新将领默认 0 阶、三派全勾；kind 从 `general_11` 起（**`general_10` 永远不存在**）。
* 将领**不能删、不能插队**：删中间一位会让后面所有序号前移，存档 / 关卡 JSON / 招募表全废
  （那是不可逆的数据损坏）。要「撤掉一个刚加错的」，用 **Ctrl+Z**，或手工把末尾那几项删掉。
* **新建 / 删除单位特性**（2026.11）：
  * 「＋ 新建单位特性…」填 id + 名字 + 照谁复制（效果照抄、短名不抄）；
  * 「删除单位特性」会**连正在挂它的兵种一起摘掉**（不留指向空 id 的记录）；
  * 特性 id 不能改（它是 `unit.unit_traits` 里的键），起错了删掉重建。
* **新建 / 删除将领特性**（2026.11.3）：
  * 「＋ 新建将领特性…」填 id + 名字 + 照谁复制（效果照抄、短名不抄）；
  * 「删除将领特性」会**连正在用它的将领一起摘掉**；
  * 特性 id 不能改（它是 `unit.general_traits` 里的键），起错了删掉重建。
* 特性池里的**增删**只发生在「对某大类伤害」那一张表里（一行一个大类）：
  下拉里只会出现**还没加过**的大类；同一大类加两次会被拒（改那一行的数就行）。
* 兵种 / 建筑的 **id 不能改**（它是存档、地图 JSON、命令流里的键）——
  起错了就删掉重建。

## 七、已知取舍（写在这里，免得以后有人以为是 bug）

| 现象 | 为什么 |
|---|---|
| 科技页已移除 | 2026.11：科技只在 `tools/tech_editor` 里改（它还要管派系池与槽位表）；本工具碰不到 `tech.*` |
| 科技的效果键在哪里登记 | `tools/tech_editor/model.py` 的 `TECH_EFFECT_KEYS`（与 `logic/tech.gd` 的 `default_effects()` 双向对齐，测试会盯着） |
| 大本营的**限制键 / 分档读条**不在界面上 | `need_generals`（升到这一级要几名将领）、`max_generals` /
  `max_techs` / `max_tech_tier` / `retinue_cap_bonus`、以及 2026.11 的 `time_by_generals`
  （三本按将领数分档：3 将 60s / 4 将 40s / 5 将 20s）都只能手改 config —— 这些是「规则」不是「数值」，
  界面上只放 `cost / time_sec / hp_mult` 三个真正天天调的。 |
| 建筑升级表的**血量只有倍率** | 游戏里的口径就是倍率（等级 × 科技都乘在基础血量上，不叠着乘）；编辑器在下面把换算结果写出来了 |
| 建造时间默认 0（瞬发） | 与「加这一栏之前」逐位一致。想让它有读条就把数字填上（读条期间不开火，`building_view` 会画一条进度条） |
| 单位地图上是**圆盘 + 一个字**，不是美术 | 需求就是这么定的（「只显示一个字作为其 2D 图像」+ 随后补的「要保留圆盘底，也给将领做圆盘底的描边」）：地图上的单位 = 阵营色圆盘 + 一个深色的字，将领那圈描边更粗。建筑仍然是色块（`color` 字段） |
| 建筑的 `blocks_*`（格级 / 本体级阻挡）不在界面上 | 新建筑有一份「格子不封、本体挡敌方」的默认值，够用；要精细调就手改那几个键 |
| 快捷键别用 N / P / E / G / 数字 1~3 | 那几个键游戏里已经占用了（区划名字 / 暂停 / 刷敌人 / 选将领）；填了会把它们抢走 |
| 特性填的是**比例**（0.25）不是百分数（25） | 与「建筑 · 远程免伤」（0.9 = 90%）同一个口径，而且写进文件的就是游戏读的那个数；百数写法会让 25 变成 **2500%**。界面上「加一条」的缺省已经是 0.25，将领特性的效果摘要会换算成 `25%` 给人看 |
| **加 / 删**一条特性之后，那一小块的排版会变（嵌套字典被展开） | `configfile` 往多行字典尾部插键时缩进按「最后那个子项的值」算 —— 而 `traits` 最后一项常常是 `attack_vs_class` 那个嵌套字典，插出来的键会歪。所以**结构改动整块重写**、**改值只动一行**（两种都有断言钉着）。这不是 bug，也不需要手对齐 |
| 将领自己没有一份 `traits` | 游戏侧就是「将领按所属兵种继承特性」（`unit.create` 抄到单位身上）；给将领单独加强请用**将领特性**（池里一条 + 指定给某位将领） |
| 默认配置里**看不到任何将领特性** | `unit.general.trait_ids` 默认全是 `""`（= 谁都没有）。想看到效果：给某位将领选一条，或在池里新建一条 —— 这是刻意的，加功能不该偷偷改数值 |
| 编辑器不检查**地图**里引用的 id | 地图（`data/maps/<id>/map.json`）里预置单位 / 建筑用的是同一批 id；删掉一个兵种后，老地图里那一项会走兜底值。地图编辑器那一侧管不了这个，改数据的人心里要数 |
| 单位页那张表单在 1080p 上**装不下**（能滚是对的） | 加了「特性」之后长枪兵那张比 978px 更高（视野半径那一轮已经是 1032px）。同建筑页那三张（1725 / 1725 / 1262px）一样：**能滚是正常的**，「装得下就不许滚」那条见 `docs/route.md` 31.6 |
| 「原生」没有复选框外的地方可看 | 备战页右面板只有王朝 / 帝国两枚按钮（用户拍板），所以**只勾「原生」的将领不会出现在任何备战页上**；想让它出现就再勾一个王朝或帝国 |
| 加出来的将领**招不出来** | 用户拍板「只加数值档，不进招募九宫格」：它不在 `recruit.zone.list` 里，只能由关卡摆放 / 开局获得。想让它可招募就手工往那张表加一条（本工具不代写） |
| 「成长（0 阶）」那一栏只在 0 阶将领身上出现 | 数值是**全局一份**（`unit.general.growth`），但 1~3 阶一点不吃 —— 给它们输入框只会让人以为改了有用 |
