# DAEEM 科技编辑器

改**游戏里所有已存在科技的数值 / 文案 / 槽位**的工具。
它写的文件是 `daeem/data/config.json` —— 也就是 `logic/config.gd` 读的那一份
（**唯一**的一份数值表）。地图编辑器改地图、战役编辑器改关卡、单位编辑器改
兵种 / 建筑 / 单位特性 / 将领特性；本工具负责 **科技**，四者互不重叠。

Python + tkinter，**零第三方依赖**，与另外三个编辑器同一套界面风格与启动习惯。

> **「科技」具体指什么？**
> `tech.list`（原生 9 条）、`tech.clan_list`（派系池：王朝 5 + 帝国 6 + 两派共用 2）、
> `tech.max_active` / `tech.gold_per_sec_by_tier`（上限与每阶每秒扣金）、
> 以及 `clan.list[].tech`（**每派科技页的 9 个槽位**）。
>
> 本工具编辑的是**已经存在的键**，不会替游戏发明新科技。
> 加新科技的步骤见第四节末尾。

## 一、怎么打开

| 方式 | 命令 |
|---|---|
| **双击**（设计师用这个） | `dev_gd_a/tools/tech_editor/tech_editor.bat` |
| 命令行 | `python dev_gd_a/tools/tech_editor` |
| 改另一份配置（对照 / 试验） | `python dev_gd_a/tools/tech_editor 别的配置.json` |
| 拖一份 json 到 bat 上 | 同上（拖进去的那一份） |
| 不开窗口，自检一遍 | `python dev_gd_a/tools/tech_editor --selftest` |

`--selftest` 会把「游戏真的会读的那些数」逐条打印出来（每页的每个字段、它落在
config 的哪条路径、当前值、游戏里的样子），并验一遍「改一处写回 → 改回来与原文
逐字节一致」。怀疑编辑器与游戏漂了就先跑它。

> ★ 为什么没有「打开文件」：科技数值**只有这一份**，打开编辑器就是为了改它。
>   地图编辑器要打开不同的地图，所以那边有导入 / 导出；这边直接落在
>   `<工程>/data/config.json`。

## 二、界面

```
┌──────────────────────────────────────────────────────────────┐
│ DAEEM 科技编辑器     config.json   ● 未保存  [撤销][重做][重载][保存] │
├──────────────┬───────────────────────────────────────────────┤
│ 科技          │ 科技 · 建筑加固  二本 · 1 条效果 · 1 金/秒      │
│  ▾ 全局       │ 原生科技（tech.list）里的第 7 条……             │
│  ▾ 原生科技   │                                               │
│  ▾ 派系科技   ├───────────────────────────────────────────────┤
│  ▾ 科技页     │ 文案 / 基础 / 效果                             │
│              │ 每个数值一行：名称 [输入框] 单位  说明          │
│              ├───────────────────────────────────────────────┤
│              │ 游戏里的样子（科技格 / 悬停说明预览）          │
│              │ ⚠ 跨字段不合理的组合（只提示，不阻止保存）      │
├──────────────┴───────────────────────────────────────────────┤
│ 状态栏：上一次操作的结果                                       │
└──────────────────────────────────────────────────────────────┘
```

> ★★ 左栏是 **Treeview**（不是一摞按钮）。原来是「画布 + 一排圆角按钮」，滚动时
>   每个按钮其实是 `tk.Button` 上盖一层 Canvas（两个子窗口），两者重绘顺序不同步，
>   于是**下滑之后按钮里的文字会错位 / 撕裂**（用户报的）。Treeview 是单个控件自己
>   滚条目，不会撕裂；另外三个编辑器的左侧列表本来也都是 Treeview。

左栏分四组（全部按 `config.json` 里实际存在的条目**现算**）：

| 分组 | 是什么 | 写的是哪一块 |
|---|---|---|
| 全局 | 同时启用上限 + 每阶每秒扣金 | `tech.max_active` / `tech.gold_per_sec_by_tier` |
| 原生科技 | `tech.list` 里的每一条（原生派系用） | `tech.list[i].{name,line,desc,tier,effect.*}` |
| 派系科技 | `tech.clan_list` 里的每一条（王朝 / 帝国 / 共用） | `tech.clan_list[i].{…}` |
| 科技页 | 每派科技页的 9 个槽位 | `clan.list[i].tech[0..8]` |

操作习惯（与单位编辑器相同）：

* 输入框里改完 **按 Enter**（或点别处）生效；**打错字不会写坏数据**，状态栏说一句，
  输入框恢复原值。
* **Esc**：放弃这一格的改动、恢复原值。
* **Ctrl+S** 保存 · **Ctrl+Z / Ctrl+Y** 撤销 / 重做 · **F5** 从磁盘重读。
* 数字超出合理范围会被**夹住**（如阶只允许 1~3、比例 ≤ 上限），状态栏会说明夹到了多少。
* **左栏可以直接滚**（滚轮 / 拖动 / 方向键）：滚轮停在左栏时只滚列表，
  不会把右边的表单一起带着滚。
* 顶栏 `● 未保存` = 有改动还没写回文件。
* 表单装得下时不能滚（滑块铺满 = 固定住），只有真的装不下才滚。

### 百分数字段

比例类效果（`food_production_mult` / `unit_speed_mult` / …）是**百分数**：

* 界面上显示 / 输入的都是**百分数**（`50%`）；
* 写进 config 的是**小数**（`0.5`）—— 与游戏读取口径一致；
* 所以 `50` 和 `50%` 都等于 0.5，`12.5` = 12.5%。

其余字段是普通数字（阶 / 每秒速率 / 绝对值增量），直接按数字输入。

## 三、每个字段落在 config.json 的哪一行

游戏侧读这些键的唯一位置是 `logic/config.gd` 的 `_cache_techs()`
（`tech.list` / `tech.clan_list` / `tech.max_active` / `gold_per_sec_by_tier`）；
规则与效果聚合在 `logic/tech.gd`。**改键名要三处一起改** ——
`test_model.py` 的第 [3] 组会去 `config.gd` / `tech.gd` 里逐条找。

| 界面上的字段 | config.json 里的位置 | 游戏里是什么 |
|---|---|---|
| 同时启用上限 | `tech.max_active` | 玩家同一时间最多能启用几条（默认 3） |
| N 阶每秒扣金 | `tech.gold_per_sec_by_tier[N-1]` | 启用中的科技按**阶**每秒扣金（维持费） |
| 名字 / 格子小字 / 悬停详情 | `tech.<表>[i].name` / `.line` / `.desc` | 命令卡那一格的两行 + 悬停说明 |
| 阶（第几行） | `tech.<表>[i].tier` | 科技页第 N 行 = N 阶；要求大本营等级够才点得动 |
| 效果 · <名称> | `tech.<表>[i].effect.<键>` | 这条科技的实际加成（比例按百分数编辑） |
| 科技页 · 第 N 格 | `clan.list[i].tech[N-1]` | 这一派科技页上摆的是哪条科技（空串 = 空位） |

游戏读这些数时会再做一层兜底（`maxi` / `maxf` / `clampf`，见 `config.gd` 的
`_cache_techs()`），所以这里填了 0 或负数不会让游戏崩，但**可能让一条科技变成
空规则**；「⚠ 提示」就是用来提前发现这种组合的。

### 科技页的 9 格是**列优先**排的

科技页在游戏里固定 3×3、**行 = 阶**。所以 `clan.list[].tech` 这个数组的顺序是
「列1上中下 → 列2上中下 → 列3上中下」：

```
第 1 格(一本,左)  第 4 格(一本,中)  第 7 格(一本,右)
第 2 格(二本,左)  第 5 格(二本,中)  第 8 格(二本,右)
第 3 格(三本,左)  第 6 格(三本,中)  第 9 格(三本,右)
```

* 填**科技 id**（必须在 `tech.list` / `tech.clan_list` 里存在）；**留空 = 空位**
  （游戏里画灰框、不可点、不弹悬停）。
* 编辑器会给出几类提示（只提示、不阻止保存）：
  * 填了**找不到**的 id → 游戏会把那一格当空位；
  * 同一个 id 在这张表里**出现两次**；
  * 单条科技上还有：`阶` 与它所在的**位置**对不上（第 1 位应该是一本）、
    效果键**不在注册表**里（游戏会静默忽略）、这一条**一条效果都没有**、
    id 在两张表里**重复**（`config.gd` 保留先读到的那一条）。

### 加一条新科技

1. 先在 `config.json` 里把条目写好（`id/tier/name/line/desc/effect`）；
2. 想让它出现在某一派的科技页上 ⇒ 把 id 填进那一派的槽位页；
3. 效果键如果游戏侧**还没读**，先在 `logic/tech.gd` 的 `default_effects()` 里登记，
   再在 `model.py` 的 `TECH_EFFECT_KEYS` 里加一行（界面名 / 单位 / 上下限 / 说明）；
4. 跑一遍 `test_model.py`：它会验「注册表 ↔ `tech.gd`」以及页数 = 条目数。

> ★ **只编辑已经存在的键**：某条科技没写 `food_production_mult`，表单里就不会有那一行。
>   要加一个新效果键，请先在 `config.json` 里写上（并在 `logic/tech.gd` 的
>   `default_effects()` 里登记），再回来改数值 —— 这样「界面少一行」永远等价于
>   「数据里没有这一条」，不会出现「编辑器以为有、游戏里其实没有」。

## 四、文件 / 模块

| 文件 | 职责 |
|---|---|
| `configfile.py` | 带注释 JSON 的**原地最小改动**读写（与 `unit_editor/configfile.py` 同一份拷贝；改一边要改另一边） |
| `model.py` | 科技页的现算生成 + 效果键注册表 + 字段描述 / 解析 / 夹取 / 提示 / 预览（无界面） |
| `app.py` | tkinter 界面；主题与「重建不闪白」跟 unit_editor 同一套；左栏是 Treeview（25 页起步，可滚） |
| `__main__.py` | 命令行入口 + `--selftest`（会把科技页也逐页打印） |
| `test_model.py` | 数据层测试（文本原地改动 / 字段路径 / 百分数 / 提示 / 契约 / **科技页与槽位**） |
| `test_app.py` | 界面测试（真建 Tk 窗口：改值 / 打错字 / 撤销 / 保存 / 重载 / **科技页 / 槽位 / 左栏**） |
| `tech_editor.bat` | 双击启动（与 `unit_editor.bat` 同一套坑：`start "" pythonw`、路径去 `..`、CRLF） |

## 五、写入策略：**只动改过的那几个字符**

`configfile.py` 不整份重排 JSON，而是「按字符区间做一次拼接」：

* 没改就保存 → **逐字节等于原文件**（有断言钉着）；
* 改一个数字 → 全文件**只有那一行**变化（实测：一个科技效果值就一处 diff）；
* 改回原值 → 文本**逐字节回到原样**（前提是原写法是规范数字，例如 `0.1` ——
  手写的 `0.10` 会被规范成 `0.1`，这是文本层的已知口径）。

为什么不 `json.dump` 整份重写：这份文件是**手写 + 带注释**的（那些 `"_comment"`
就是文档），而很多条目刻意压在一行里。整份重排会让上千行产生格式噪音，
`git blame` / review / 回滚全废。

> ★ **尾逗号**：Godot 的 JSON 解析器容忍尾逗号，Python 的 `json` 不容忍。
>   编辑器**读**的时候容忍，**写**出来的永远是严格合法的 JSON。

## 六、测试

```bat
python dev_gd_a\tools\tech_editor\test_model.py    :: 数据层
python dev_gd_a\tools\tech_editor\test_app.py      :: 界面（没有图形界面时自动跳过）
```

两套测试都**只动包目录下的 `.tmp_tech_*` 副本**，跑完会删掉；
最后一条断言钉着「真 `config.json` 在整个测试过程中一字未改」。
`test_model.py` 还去 `logic/tech.gd` / `logic/config.gd` 里逐条找键 ——
游戏侧改了键名而这里没跟上，它会当场红，而不是让游戏静默用兜底值。

## 七、已知取舍

| 现象 | 为什么 |
|---|---|
| 只能改**已经存在**的科技 / 效果键 | 工具不替游戏发明规则：界面少一行 == 数据里没有这一条 |
| 阶只允许 1~3 | 科技页固定 3 行（一本 / 二本 / 三本） |
| 改回原值有时不是逐字节原样 | 手写的 `0.10` / `1.50` 会被规范成 `0.1` / `1.5`；值本身不变 |
| 「原生」没有槽位页 | `clan.list` 里原生那一条没有 `tech` 键（它直接用 `tech.list`），编辑器不去编不存在的键 |
| 编辑器不新增 / 删除科技条目 | 这里只调数值；增删条目要连 id、槽位、效果键一起考虑，放 config 里做更安全 |
