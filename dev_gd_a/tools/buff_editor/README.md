# DAEEM buff 编辑器

改**游戏里所有 buff 的数值**的工具。
它写的文件是 `daeem/data/config.json` —— 也就是 `logic/config.gd` 读的那一份
（**唯一**的一份数值表）。地图编辑器改地图、战役编辑器改关卡、单位编辑器改
兵种 / 建筑 / 科技；本工具只负责 **buff**，四者互不重叠。

Python + tkinter，**零第三方依赖**，与另外三个编辑器同一套界面风格与启动习惯。

> **「buff」现在指什么？**
> 游戏里目前只有**一条** buff：单位详细信息右栏那个「士」方块 = **士气**。
> 它的规则在 `logic/morale.gd`，悬停说明在 `view/hud.gd`，数值全部来自
> `config.morale.*`；另外 `combat.damage_reduction_cap`（减伤封顶）同时管
> 士气免伤和骑手的「对远程减伤」，算是这条 buff 的一部分，所以也放在本工具里。
>
> 本工具编辑的是**已经存在的键**，不会替游戏发明新 buff。加新 buff 的步骤见第三节。

## 一、怎么打开

| 方式 | 命令 |
|---|---|
| **双击**（设计师用这个） | `dev_gd_a/tools/buff_editor/buff_editor.bat` |
| 命令行 | `python dev_gd_a/tools/buff_editor` |
| 改另一份配置（对照 / 试验） | `python dev_gd_a/tools/buff_editor 别的配置.json` |
| 拖一份 json 到 bat 上 | 同上（拖进去的那一份） |
| 不开窗口，自检一遍 | `python dev_gd_a/tools/buff_editor --selftest` |

`--selftest` 会把「游戏真的会读的那些数」逐条打印出来（每条字段的 config 路径、
当前值、悬停文案），并验一遍「改一处写回 → 改回来与原文逐字节一致」。
怀疑编辑器与游戏漂了就先跑它。

> ★ 为什么没有「打开文件」：buff 数值**只有这一份**，打开编辑器就是为了改它。
>   地图编辑器要打开不同的地图，所以那边有导入 / 导出；这边直接落在
>   `<工程>/data/config.json`。

## 二、界面

```
┌──────────────────────────────────────────────────────────────┐
│ DAEEM buff 编辑器       config.json   ● 未保存  [撤销][重做][重载][保存] │
├──────────────┬───────────────────────────────────────────────┤
│ Buff 列表     │ 士  士气「士」  90 / 100                       │
│  ▸ 士气 士    │ 整支部队共享的士气……                          │
│              ├───────────────────────────────────────────────┤
│ （以后新增）  │ 基础 / 阈值 / 生命 / 伤害 / 区划 / 战果        │
│              │ 每个数值一行：名称 [输入框] 单位  说明          │
│              ├───────────────────────────────────────────────┤
│              │ 悬停浮窗预览（游戏里「士」上停住时显示这段）    │
│              │ ⚠ 跨字段不合理的组合（只提示，不阻止保存）      │
├──────────────┴───────────────────────────────────────────────┤
│ 状态栏：上一次操作的结果                                       │
└──────────────────────────────────────────────────────────────┘
```

操作习惯（与单位编辑器相同）：

* 输入框里改完 **按 Enter**（或点别处）生效；**打错字不会写坏数据**，状态栏说一句，
  输入框恢复原值。
* **Esc**：放弃这一格的改动、恢复原值。
* **Ctrl+S** 保存 · **Ctrl+Z / Ctrl+Y** 撤销 / 重做 · **F5** 从磁盘重读。
* 数字超出合理范围会被**夹住**（如百分数 > 上限），状态栏会说明夹到了多少。
* 顶栏 `● 未保存` = 有改动还没写回文件。
* 表单装得下时不能滚（滑块铺满 = 固定住），只有真的装不下才滚。

### 百分数字段

`伤害` 组里的三个字段是**百分数**：

* 界面上显示 / 输入的都是**百分数**（`50%`）；
* 写进 config 的是**小数**（`0.5`）—— 与游戏读取口径一致；
* 所以 `50` 和 `50%` 都等于 0.5，`12.5` = 12.5%。

其余字段是普通数字（点 / 每秒速率 / 阈值），直接按数字输入。

## 三、每个字段落在 config.json 的哪一行

游戏侧读这些键的唯一位置是 `logic/config.gd` 的 `_cache_scalars()`
（`num("morale.…")`）；规则在 `logic/morale.gd`，悬停文案在 `view/hud.gd`。
**改键名要三处一起改** —— `test_model.py` 的第 [4] 组会去 `config.gd` 里逐条找。

| 界面上的字段 | config.json 里的位置 | 游戏里是什么 |
|---|---|---|
| 士气上限 / 初始士气 | `morale.max` / `morale.start` | 单位出生时的士气上限 / 开局值 |
| ≥ 高档阈值 | `morale.high_tier` | 达到它：快速回血 + **免伤** |
| ≥ 中档阈值 | `morale.mid_tier` | 达到它：缓慢回血 |
| ≤ 易伤阈值 | `morale.vuln_tier` | 低于它：受到伤害增加 |
| ≤ 掉血阈值 | `morale.low_tier` | 低于它：缓慢掉血；士气 0 换更快的档 |
| 高档回血 / 中档回血 | `morale.hp_regen_high` / `hp_regen_mid` | 每秒回多少生命 |
| 低档掉血 / 零士气掉血 | `morale.hp_decay_low` / `hp_decay_zero` | 每秒掉多少生命（**不致死**） |
| 掉血下限 | `morale.hp_floor` | 掉血最多扣到这里 |
| 士气免伤 / 士气易伤 | `morale.damage_reduction` / `vulnerability` | 受到伤害的乘数（百分数） |
| 减伤封顶（含兵种特性） | `combat.damage_reduction_cap` | 所有减伤来源**相加后**的上限 |
| 己方区划回升 | `morale.regen_ally` | 站在己方 / 友方区划里每秒 +多少 |
| 敌方区划疲惫 | `morale.decay_enemy` | 站在敌方 / 中立区划里每秒 -多少 |
| 被包围区划疲惫 | `morale.decay_surrounded` | 己方区划被包围时每秒 -多少 |
| 破敌 / 斩将 / 掠地加成 | `morale.boost_kill` / `boost_leader` / `boost_capture` | 事件发生时立即 +多少 |

游戏读这些数时会再做一层兜底夹取（`maxf` / `clampf`，见 `config.gd`），
所以这里填了 0 或负数不会让游戏崩，但**可能让 buff 变成一条空规则**；
右上角预览与「⚠ 跨字段提示」就是用来提前发现这种组合的。

### 加一条新 buff

本工具**不会**替游戏创造新 buff。真要加，顺序是：

1. **游戏侧先读它**：在 `config.json` 加一段（例如 `buff.xxx.*`），
   在 `logic/` 里读取并生效；
2. 在 `model.py` 的 `BUFFS` 注册表里加一条 `Buff(...)`：
   `id` / `name` / `icon` / `path`（config 段）/ `intro` / `fields`（每个字段的
   `key`、界面名、分组、单位、上下限、help；比例类用 `kind="percent"`）；
3. 界面、README 的字段表不用改（列表与表单都是按 `BUFFS` 生成的）；
4. 在 `test_model.py` 的字段集合与契约用例里补一条，`test_app.py` 一般不用动
   （断言的是「注册表里有几条就建几个框」，但具体数字要一起改）。

这就是为什么只有一条士气也值得做成「注册表」：下一条 buff 只加数据，不动界面。

## 四、文件 / 模块

| 文件 | 职责 |
|---|---|
| `configfile.py` | 带注释 JSON 的**原地最小改动**读写（与 `unit_editor/configfile.py` 同一份拷贝；改一边要改另一边） |
| `model.py` | buff 注册表 / 字段描述 / 解析 / 夹取 / 跨字段提示 / 悬停文案预览（无界面） |
| `app.py` | tkinter 界面；主题与「重建不闪白」跟 unit_editor 同一套 |
| `__main__.py` | 命令行入口 + `--selftest` |
| `test_model.py` | 数据层测试（文本原地改动 / 字段路径 / 百分数 / 提示 / 游戏侧契约） |
| `test_app.py` | 界面测试（真建 Tk 窗口：改值 / 打错字 / 撤销 / 保存 / 重载） |
| `buff_editor.bat` | 双击启动（与 `unit_editor.bat` 同一套坑：`start "" pythonw`、路径去 `..`、CRLF） |

## 五、测试

```bat
python dev_gd_a\tools\buff_editor\test_model.py    :: 数据层
python dev_gd_a\tools\buff_editor\test_app.py      :: 界面（没有图形界面时自动跳过）
```

两套测试都**只动包目录下的 `.tmp_buff_*` 副本**，跑完会删掉；
最后一条断言钉着「真 `config.json` 在整个测试过程中一字未改」。
`test_model.py` 还去 `logic/config.gd` 里逐条找字段路径 —— 游戏侧改了键名而这里没跟上，
它会当场红，而不是让游戏静默用兜底值。
