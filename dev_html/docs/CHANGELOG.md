# 变更记录

> 按版本倒序。设计细节见 [`multiplayer.md`](multiplayer.md)；玩法见 [`../README.md`](../README.md)。

每一版都记三件事：**加了什么**、**修了什么坑**、**测试规模**。
"坑"是这份记录里最有价值的部分 —— 它们全都出现在"真实 `main.js` 跑起来"这条路径上，

## v0.6 —— 准备界面

### 加了什么

- **准备界面**：进房间后先停在这里，显示双方阵营与"谁已准备"。**双方都点准备**（或按 `R`）
  之后房主宣布开战、按 `CONFIG.pvp.countdownSec`（默认 3 秒）倒计时，然后世界才被建出来。
- **再来一局**：一局结束后按 `R` / 点「↻ 再来一局」回到准备界面，不用刷新页面。
- **服务器新增两条转发规则**：`ready`（广播全房间，带服务器盖章的阵营）、
  `start`（**只认房主**，客机伪造的会被丢弃）。
- `startMatch()` 现在按同一份名单、同一套确定性规则为**每一方**建基地与部队 ——
  房主和客机各自算，结果必然一致，不再依赖"谁先谁后"。

### 修了什么坑

- **★ 线上事故：一打开页面就显示"P1 赢了"。**
  名单 `FACTION_ROSTER` 有 8 个席位，但房主先进房间时**只有 p1 有基地**；
  胜负判定拿"名单人数"当分母，于是第 0 帧就算出「8 个玩家只剩 1 个活着」→ 直接判 p1 获胜。
  - **直接修**：分母改为"在场的阵营"（`spawnedFactions()` = 已建出基地的那些），
    并要求至少两个玩家在场才谈输赢。
  - **结构性修**：准备界面让"只有一个人在场"时根本不放行、世界也不建出来，那段窗口从根上没有了。
- **缺字段的旧快照会把已结算画面打回进行中** —— 正确行为是"保持本地状态不变"。

### 测试规模

657 项 / 13 个套件（本轮新增 `net-integration-test.mjs` 的准备界面与开战断言、`net-server-test.mjs` 的 ready/start 转发）。
一键跑：`py tools/run-all-tests.py --with-server`。

## v0.5 —— 分阵营战斗

### 加了什么

- **双方各有自己的大本营**：P1 在地图中央 (12,8)，P2 在右下角 (19,11)，相距 10 格；
  选址自动避开山地；P2 及之后自带一小段城墙 + 一座箭塔（`map.js` 的 `spawnLayoutFor`）。
- **阵亡 8 秒在自家大本营复活**（`CONFIG.pvp.respawnSec`）：按单位序号围坐在大本营相邻格，
  屏幕上画复活倒计时环。**无限复活** —— 所以胜负只能靠拆家。
- **拆家分胜负**：`CONFIG.pvp.destructibleBase` 打开后大本营可被打掉，
  打掉即该方落败；结算由房主判定并随快照同步，两边显示一定一致。
- **10 分钟时限**：超时按大本营剩余血量比例判胜负。

### 修了什么坑

| 坑 | 后果 |
|---|---|
| `applyFactionLayout` 把 `state.units` **整个替换** | **房主手里只有一方的部队** —— 双方基地都在，但地图上只有 p2 的兵，根本打不起来 |
| `removeBuilding` 的"大本营不可拆"守卫**把战斗摧毁也挡住了** | 基地被打到 0 血、胜负已判，**却还站在地图上** |
| `init()` 先建的单机大本营没被清掉 | 两个大本营**叠在同一格**，`owner` 停在 `'player'` |
| "主阵营"取的是 `myFaction` 而不是名单第一个 | 客机会把 p2 摆到地图中央，**两边算出不同的世界** |
| 复活功能**泄漏进单机** | 单机里被打死的测试敌人 8 秒后复活 |
| `resetMatch` 里阵营比较写反 | 重开一局后**一个单位都不剩** |

## v0.4 —— 联机同步

### 加了什么

- **阵营参数化**（`js/faction.js`）：`p1`/`p2`/`enemy` + 单机默认 `'player'`；
  `isPlayerFaction` / `sameSide` 两条对称规则；城墙语义从"是不是 `'player'`"改成
  "是不是**我自己人**"（两个阵营时等价，所以单机行为不变）。
- **房主权威 + 服务器中继**（`js/net.js` + `net/serve.py`）：
  房主跑完整逻辑并 20Hz 广播快照；客机冻结 `update()`，只发意图、收快照、插值渲染。
- **快照**：单位/建筑/区块/资源/时间 + 后来的结算状态；坐标保留 2 位小数；
  单次约 1.6 KB，20Hz 下单人下行约 32 KB/s。
- **服务器零第三方依赖**：手写 RFC 6455 握手与帧编解码，只做静态托管 + 房间 + 转发。
- **区块占领改为每阵营独立累计**（`z.progressBy`）—— 旧实现的单一 `progress`
  会让两个玩家同时站在同一区块时**互相抵消**，谁也占不下来。
- **断线自动退回单机**（不白屏）。

### 修了什么坑

| 坑 | 后果 |
|---|---|
| `FACTION_ROSTER` 漏 import | **`#net=1` 页面直接崩**，联机功能等于不存在 |
| 快照广播写在 `updateNet()` 里，而它只被主循环调用 | `RTS.tick()` 永远测不到广播（"1 秒应发 20 条"得到 0 条）→ 新增 `RTS.frame()` |
| `net.js` 顶层读 `location` | Node 环境直接 `ReferenceError`，连单机都跑不起来 |
| 初始化时序：`initNet()` 在 `init()` 之后跑 | 房主连上前 `myFaction` 还是 `'player'` 而 `isHost` 已是 true，**点右键命令静默失效** |
| 断线退回后阵营没切回默认 | 选不中任何单位、也建不了东西（"看上去能玩其实动不了"） |
| `applySnapshot` 只写 `netPx` 没写 `px` | 渲染靠插值"看起来正常"，但 `state` 里坐标是旧的 —— **点选/射程/HUD 全错** |
| 单文件打包的模块顺序 | `const` 不像函数声明那样提升，顺序错就 `ReferenceError`；靠 `bundle-run-test.mjs` 兜住 |

## v0.3 —— 战斗与警戒（联机之前的基线）

### 有什么

- 24×16 四连通地图、A* + 直线拉平（`smoothPath` / 超覆盖 DDA 的 `segmentClear`）
- 点到哪走到哪、能走直线就走直线
- 战斗 / 警戒（静止索敌 → 先靠近 → 再攻击、追击上限）
- 城墙有血量、敌方会自己找挡路的墙拆
- 区块占领 + 资源产出
- 大本营 / 城墙 / 箭塔
- 相机（边缘滚屏 / 键盘 / 光标锚点缩放）、DPR 坐标约定 + `G` 键坐标准星

### 基线测试规模

**316 项**（`smoke_test.py` 132 + `smoke-test.mjs` 143 + `integration-test.mjs` 41）。
**这 316 项在 v0.4~v0.6 期间全部零回归** —— 联机改造没有动过单机行为。
