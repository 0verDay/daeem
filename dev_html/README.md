# RTS 原型 v0.4 —— 四连通地图 / 直线移动 / 战斗警戒 / 区块占领 / 建造 / 将领 / 联机

一个纯前端的 RTS 玩法原型，用来先跑通**基本逻辑**：地图、领地与资源、建筑、单位移动与选中、战斗与警戒。
没有依赖、没有构建工具链，双击一个 HTML 就能玩。

**v0.4 新增：多人同屏联机**（房主权威 + 服务器中继，零第三方依赖）。
不改 URL 就是纯单机，行为与 v0.3 完全一致。

## 一、怎么打开

| 方式 | 文件 | 说明 |
|---|---|---|
| **单机 · 推荐**（双击即玩） | `rts-prototype.html` | 打包好的单文件版本，直接双击用浏览器打开 |
| **联机** | 见 [`net/README.md`](net/README.md) | 起 `net/serve.py`，用 `#net=1` 打开 |
| 开发用（模块化源码） | `index.html` | 需要本地 HTTP 服务：见下方说明 |

> ⚠️ 浏览器在 `file://` 协议下会以 CORS 策略拦截 `<script type="module">`，
> 所以**直接双击 `index.html` 会白屏**（这是浏览器行为，不是代码问题）。
> 想调试模块化源码，起一个本地服务即可：
>
> ```bash
> cd dev_html
> python -m http.server 8899
> # 然后打开 http://127.0.0.1:8899/index.html
> ```
>
> 改完 `js/*.js` 或 `css/style.css` 后，重新生成单文件版：
>
> ```bash
> python tools/build_single_file.py            # 生成 rts-prototype.html
> python tools/build_single_file.py --watch    # 或开启自动重建
> ```

### 联机怎么开（三条命令）

```bash
py net/serve.py --port 8080          # 服务器上（Windows 上 python 常是占位符，用 py 更稳）
```

| 谁 | 地址 |
|---|---|
| 房主（第 1 个打开的人 → 阵营 p1） | `http://<IP>:8080/rts-prototype.html#net=1` |
| 客机（其他人 → p2 / p3 …） | `http://<IP>:8080/rts-prototype.html#net=1&room=default` |
| 只想确认服务器活着 | `http://<IP>:8080/health` |

> 腾讯云/阿里云必须先在**控制台安全组**放行 `TCP:8080`，再放行 Windows 防火墙。
> **别用 80/443**（大陆地域要 ICP 备案）；8080 免备案可立刻测。
> 完整部署与排错清单见 [`net/README.md`](net/README.md)。

## 三、操作方式

| 操作 | 说明 |
|---|---|
| `1` / `2` / `3` | 快速选中三个将领 |
| 左键 | 选中将领 / 选中建筑；`Shift` + 左键多选 |
| 右键 | 命令选中将领移动到**鼠标所指的位置**（点到哪走到哪；点到山/城墙/建筑时自动走到最近可达处）。**右键命令会中断当前交战** |
| （自动） | **警戒**：单位静止且没有目标时，会自动索敌并主动接敌，不需要玩家操作（规则见第四节 7） |
| `B` / `T` | 进入城墙 / 箭塔建造模式，左键放置，右键或 `Esc` 退出 |
| `X` / `Delete` | 拆除选中建筑（大本营不可拆） |
| `W A S D` / 方向键 | 平移视野；滚轮**以光标为锚点**缩放；`F` 适应视野 |
| `N` | 显示 / 隐藏区块名；`P` 暂停；`E` 刷一个测试敌人；`H` 帮助 |
| `G` | **坐标调试准星**：红叉=鼠标所指的世界坐标，绿圈=判定出的地块中心，两者必须重合 |

浏览器控制台里有调试句柄 `window.RTS`，例如：

```js
RTS.state.units.length      // 单位数
RTS.state.ownedTiles        // 己方地块数
RTS.spawnEnemy()            // 刷一个测试敌人
RTS.tick(1/60)              // 手动推进一帧逻辑（= update，客机在联机下会直接返回）
RTS.frame(1/60)             // ★ 推进一整个主循环帧（update + 联机快照广播），联机调试用这个
RTS.drawOnce()              // 手动渲染一帧
RTS.screenToWorld(600, 400) // 屏幕点 → 世界坐标
RTS.worldToTile(830, 500)   // 世界坐标 → 地块
RTS.state.view              // 视口尺寸与 dpr
RTS.CONFIG                  // 全部可调参数（含 CONFIG.combat）
RTS.CONFIG.combat.enabled = false   // 运行时关掉攻击 / 警戒，只看移动
RTS.segmentClearFor(state, {x,y}, {x,y}, 'player')  // 这条直线能不能走
RTS.smoothPathFor(state, [{x,y}, ...], 'player')    // 折线拉直的结果

// 联机相关
RTS.netStatus()             // { active, isHost, faction, peers, snaps, error, fallback }
RTS.myFaction()             // 我控制的阵营（单机 = 'player'）
RTS.netGoOffline()          // 手动退回单机模式
RTS.handleNetWelcome({isHost:false, faction:'p2', roster:['p1','p2']})  // 模拟服务器分配身份
```

## 三·五、联机（v0.4 起）

完整部署与排错见 [`net/README.md`](net/README.md)；
**架构决策、协议、踩的坑、测试体系见 [`docs/multiplayer.md`](docs/multiplayer.md)**；
版本变更见 [`docs/CHANGELOG.md`](docs/CHANGELOG.md)。这里只说规则与边界。

### 架构：房主权威 + 服务器中继

- **房主**（第 1 个进房间的人，阵营 `p1`）跑**完整的游戏逻辑**，每 20Hz 广播权威快照。
- **客机**（`p2` / `p3` …）`update()` 被**冻结** —— 不跑逻辑，只发操作意图、收快照、插值渲染。
  它的相机 / 选中 / HUD / 绘制照常跑，所以操作手感是即时的。
- **服务器是哑的**：只做静态托管 + WebSocket + 房间 + 两条转发规则
  （客机的 `cmd` → 只给房主；房主的 `snap` → 广播给其他人）。
  它**不 import 任何游戏模块**，所以不需要把 `main.js` 拆成 DOM 层与逻辑层，
  也不会出现「服务端规则与客户端规则不一致」这类最难查的 bug。

### 为什么权威必须只有一份

如果每个客户端各跑一局再互相同步，那就是「两个人各玩各的」—— 两边状态会各自漂移，
永远不会收敛。**必须有一方说了算。**

### 同步了什么

| 数据 | 字段 |
|---|---|
| 单位 | `id / faction / kind / px / py / hp / moving / facing / hotkey` |
| 建筑 | `type / tx / ty / owner / hp` |
| 区块 | `owner / progress` |
| 其他 | `resources / ownedTiles / time` |

**同步的是结果，不是路径。** 客机右键只发「哪些单位、走到哪个像素点」，
路径由房主算（它才知道最新的城墙位置）—— 顺带避免了路径欺骗。

**实测单次快照约 1.6KB**，20Hz 下单人下行约 32KB/s，小水管服务器带 6 人没问题。

### ★ 准备界面（v0.6：双方都点「准备」才开战）

进房间后**先停在准备界面**：显示双方阵营、谁准备好了。**双方都点准备**后，房主宣布开战，
走 `CONFIG.pvp.countdownSec`（默认 3 秒）倒计时，然后世界才被建出来、正式开打。

操作：按 **`R`** 或点侧栏的「✅ 准备」按钮。一局结束后同一个按钮变成「↻ 再来一局」。

这**不只是个门面**，它顺带从结构上消灭了一类线上事故：

> 名单 `FACTION_ROSTER` 有 8 个席位（p1..p8），但房主先进房间时**只有 p1 有基地**。
> 早期实现拿"名单人数"当胜负判定的分母，于是第 0 帧就算出「8 个玩家只剩 1 个活着」
> → **直接判 p1 获胜**。线上表现就是两个玩家一打开页面就显示"P1 赢了"，完全没法玩。
>
> 现在准备阶段**只有一个人时永远不会放行**，世界也不会被建出来，所以那段窗口从根上没有了。

实现上它也是「双方建出同一个世界」的保证：`startMatch()` 按同一份名单、同一套确定性规则
（`spawnLayoutFor`）为**每一方**建基地与部队 —— 房主和客机各自算，结果必然一致，
不再依赖"谁先谁后"这种巧合。

### 阵营模型（`js/faction.js`）
阵营从 `'player' | 'enemy'` 两个字符串字面量，参数化成：

| 取值 | 含义 |
|---|---|
| `'p1'` … `'p8'` | 玩家席位（第 1 个进房间的是 p1） |
| `'enemy'` | NPC / 调试用测试敌人 |
| `'player'` | **单机模式的默认阵营**，等价于 P1 —— 保留是为了让单机行为与传统测试逐位不变 |

两条方向相反的规则，别搞混：

- `isPlayerFaction(f)` —— 这个阵营是不是**玩家控制的一方**？（决定它是否索敌 / 占区块 / 回血）
- `sameSide(a, b)` —— 这两者是不是**同一方**？（决定是否互相攻击、城墙是否放行）

**城墙语义**：`blocks(faction)` 的判定基准从「是不是 `'player'`」改成
「是不是**我自己人**」。只有两个阵营时这两种写法等价（所以单机行为不变），
但联机下 `p2` 的城墙对 `p1` 必须阻挡 —— 旧写法会错误地放行。

### ★ 对战规则（v0.5：让两个玩家真的打得起来）

只做三件事，就能从「互相看到」变成「分阵营战斗」。全部由 `CONFIG.pvp` 控制，
且**只在联机模式生效**（`state.pvpEnabled`，单机一个字节都不变）。

**1. 双方各有自己的基地（`map.js` 的 `spawnLayoutFor`）**

| 阵营 | 大本营 | 说明 |
|---|---|---|
| P1（房主） | 地图中央 (12, 8) | 沿用原版点位，单机也是这里 |
| P2 | (19, 11) | 关于地图中心对称，相距 10 格 |
| P3…P8 | `PVP_POINTS` 其余点位 | 预留 |

- 选址会自动避开山地（`nearestWalkable` 从内向外找最近的可行走格）。
- 出生点只由**名单顺序**决定，不由「我是谁」决定 —— 否则客机会把 p2 摆到地图中央，
  而房主那边 p1 也在中央，两边算出不同的世界。
- P2 及之后还会自带一小段城墙 + 一座箭塔（"阵地感"，也顺带验证建筑阵营归属）。

**2. 阵亡后 8 秒在自家大本营复活（`CONFIG.pvp.respawnSec`）**

没有复活的话，死一次就只能干看着 —— 联机测试根本进行不下去。

- 复活位置按**单位序号**围坐在大本营相邻格（`general-p1-2` → 第 2 个位置），
  所以每次复活的站位是固定、可预测的；该格不可通行时自动顺延。
- 客机上阵亡的单位从快照里消失、复活后重新出现（快照只发存活单位）。
- 屏幕上有**复活倒计时环**（在大本营位置，只画自己这一方的）。
- **是无限复活** —— 所以胜负只能靠拆家，不能靠杀光对方。

**3. 打掉对方大本营 = 该方落败（`CONFIG.pvp.destructibleBase`）**

- 打开后大本营血量可以被真正打到 0（单机保持"保底 1 血、永远打不掉"）。
- 结算由房主判定，**随快照同步**给客机（`snapshot.match`），所以两边显示的结果一定一致。
- 结束后画一条结算横幅（你赢了 / 你输了 / 平局），并写进事件日志。
- `CONFIG.pvp.timeLimitSec`（默认 600 秒）到点按「大本营剩余血量比例」判胜负，防止无限拖时间；
  设为 0 则不限时。

> **注意**：大本营不能**被拆除**（X / Delete），只能**被打掉** —— 这两条路径在
> `removeBuilding(state, b, force)` 里用 `force` 参数区分。战斗摧毁必须传 `force = true`，
> 否则会出现「基地被打到 0 血、胜负已判，但它还站在地图上」的坏状态。

> **另一个已修的坑**：胜负判定的**分母必须是"在场的阵营"，不是"名单里的席位"**。
> `FACTION_ROSTER` 有 8 个席位（p1..p8），但开局只有房主 p1 进了房间、也就只有 p1 有基地。
> 早期实现拿名单当分母，于是第 0 帧就得出「8 个玩家只剩 1 个活着」→ **直接判 p1 获胜** ——
> 线上表现就是两个玩家一打开页面就显示"P1 赢了"，完全没法玩。
> 现在只用 `spawnedFactions()`（已经建出基地的阵营）来判断，一个人玩永远不会"分出胜负"。
> 回归测试在 `net-integration-test.mjs` 的 11a 节与 `bundle-run-test.mjs`（直接验产物）。

### 区块占领改成了每阵营独立累计

旧实现只有一个全局 `z.progress`。联机下两个玩家同时站在同一区块会**互相抵消**
（一个加、一个减，谁也占不下来）。现在进度存在 `z.progressBy[阵营]` 里，
各记各的，谁先到 1 谁拿走。

### 已知限制（有意不做）

| 限制 | 说明 |
|---|---|
| 房主是一个人，不是一台服务器 | 房主卡 → 全员卡；房主关页面 → 客机会被服务器提升为新房主，但世界状态会重新同步 |
| 没有反作弊 | 快照由房主生成。服务器会给 `cmd` **盖章发送者阵营**，所以客机无法操控房主的单位 |
| 没有断线重连 | 掉线即退出，重新打开作为新玩家重新同步 |
| 客机约 150ms 延迟 | 50ms 快照周期 + 100ms 插值缓冲，**没有客户端预测** |
| 没有状态压缩 | 整包快照。玩家多 / 地图大了要改增量同步 |
| `ws://` 不加密 | 测试够用。上域名 + HTTPS 时必须是 `wss://` |
| 单格单建筑 | 一个地块只能有一个建筑，两个玩家抢同一格会失败 |
| 无限复活 | 所以胜负只靠拆家。想要"杀光对方算赢"就得给单位加生命次数 |
| 阵营是固定的 p1/p2 | 目前没有队伍/结盟概念，每个阵营各自为战 |
| 没有战争迷雾 | 客机能看见全场（包括对手的位置） |

## 四、已实现的规则

### 1. 地图
- **四连通**正方形地块，**24 × 16（数量不变）**，每格 `CONFIG.cell = 120px`。
- 地图是为**建筑**设计的地块，**单位不要求与地块一一对应**：多个单位可以叠在同一格。
- 地形：草地（正常）、森林（可通行，速度 ×0.5）、山地（不可通行）。
- 开局会做一次**连通性修正**：从大本营四连通到达不了的"可通行格"直接变成山，
  保证寻路永远不出现"看着能走其实走不到"。当前地图 15 格山体、369 格可通行，只有一个连通区域。
- 单位沿 A* 给出的地块路线移动，路线会被**拉直**（能走直线就走直线），终点是玩家点击的位置（见下面「单位移动」一节）。

### 1.5 单位移动（点到哪走到哪 + 能走直线就走直线）
- **点到哪走到哪**：右键的目标是**鼠标点击的那个像素位置**，不是地块中心。
  `js/unit.js` 的 `moveTo(state, 世界坐标)`：
  - 点击位置所在格可通行 → 终点就是点击的精确坐标（同格里也能"挪一小步"）；
  - 点到山 / 城墙 / 建筑的格子 → 自动改走到最近的可达格中心；
  - 寻路分两步：**A* 只负责回答"绕开山 / 城墙该走哪几个格子"**，随后
    `js/path.js` 的 `smoothPath()` 把这条格心折线**拉直**（string pulling：
    每次贪心跳到"直线可达"的最远点）。于是开阔地带退化成一条直线，
    只有真的挡着山 / 城墙时才保留拐点 —— 旧版本中间路径点全在格心上，
    所以明明可以走直线也会走成阶梯。
- **直线能不能走**由 `segmentClear()` 判定：用**超覆盖 DDA**（Amanatides & Woo）
  枚举线段"擦到"的每一个地块，包括只在线段上碰到一个角的格子，
  因此拉直不会让单位翻山、穿墙，也不会贴着山尖蹭过去。
  起点所在格不检查（单位可能正站在后来被建筑占住的格子上，必须允许它走出来）。
- **不按地块跳动**：位置是连续世界坐标，可停在格内任意处。实现见 `Unit.stepAlongPath()`：
  - 每帧距离预算 = `速度 × 格宽 × dt`（像素）；
  - 走不完一段就沿方向推进；走完一段还有余量就把多余距离带到下一段，
    因此**一帧跨多格时速度依然均匀**，不会抖动或卡顿；
  - `tx` / `ty` 只是由像素位置反算出的"所在地块"，仅用于占区块、资源、箭塔、警戒判定。
- 参考值：速度 2.4 格/秒 = 288 px/秒 = 60fps 下 4.8 px/帧。

### 1.6 大地图与视野
- **地块数量不变**（24 × 16），但每格 `CONFIG.cell = 120px` → 地图世界尺寸 **2880 × 1920**，
  比视口大得多，需要靠移动视角来看。
- **单位远小于地块**：单位半径 = `cell × CONFIG.unit.radiusFactor(0.1)` = 12px，
  直径 24px 只占地块宽度的 20%（改这个系数即可整体缩放单位）。
- **鼠标推到视野边缘即平移视角**（`CONFIG.camera.edgeScroll`）：
  - 边距 `edgeSize = 44px`，越贴边滚得越快（归一化后取平方，最大 `edgeMaxSpeed = 1500 px/s`）；
  - 鼠标离开画布、或**按住空格**时暂停滚屏；顶栏「🖱 边缘滚屏」按钮可整体开关；
  - 键盘 `WASD` / 方向键 平移，`F` 缩到看完整张地图，`Home` 把镜头移回大本营。

### 1.7 坐标与高 DPI（改渲染时务必遵守）
出现过的 bug：**鼠标所指的位置和判定出的地块错位**。根因是 canvas 后备缓冲按
`devicePixelRatio` 放大，但绘制前没有做 DPR 变换，于是画面只画在左上角 `1/dpr` 区域，
而鼠标换算是按 CSS 像素算的。现在的约定（`js/render.js` 顶部注释也写了）：

1. **相机数学与所有输入换算一律使用 CSS 像素**（`state.view.w/h`）；
2. canvas 后备缓冲 = CSS 尺寸 × dpr，绘制前 `ctx.setTransform(dpr, 0, 0, dpr, 0, 0)`；
3. 世界坐标 = 地块坐标 × `CONFIG.cell`；
4. 鼠标坐标统一走 `eventToCanvas()`（减去 canvas 的 `getBoundingClientRect()`），
   canvas 的 CSS 尺寸与 `stage.clientWidth/Height` 取同一个整数，避免拉伸造成亚像素偏差。

怀疑又错位时按 **`G`** 打开坐标调试准星：红叉是鼠标世界坐标，绿圈是判定出的地块中心，
两者必须重合；左上角还会显示 dpr、视口尺寸、缩放与换算结果。

### 2. 建筑（每格最多一个）
| 建筑 | 说明 |
|---|---|
| **大本营** | 开局自带，不可建造、不可拆除，占据 1 格；**本版不可摧毁**（被打到 0 血时保留 1 点） |
| **城墙** | 填充整个地块；**己方单位可以穿过，敌方单位不可进入**（寻路时绕行）；**有血量**（`CONFIG.building.wall.hpMax = 300`），被打光就塌、让出缺口 |
| **箭塔** | 每 0.8s 对射程内（3 格）**最近的敌人**造成 12 点**单体伤害**，己方不会被误伤 |

- 建造校验：山地不可建、已有建筑的格子不可建。
- 建造**暂时免费**（`CONFIG.economy.enabled = false` 时不扣资源；把 `CONFIG.building.*.cost` 填上再打开开关即可启用消耗）。
- 建筑挨打会**整格闪红**，血量不满时在格子底部画血条（满血不画，避免刷屏）；
  选中建筑时侧栏显示 `生命 260 / 300`。

### 2.5 城墙血量与拆墙（v0.3）
- 城墙血量 = `CONFIG.building.wall.hpMax`（默认 300），伤害与间隔见 `CONFIG.combat`：
  **每次 40 点**、节奏沿用攻击方的 `cooldownSec`（测试敌人 1.2s → 一堵墙约 9.6s 拆完）。
- **谁能拆**：任何单位锁定建筑后都能拆（`unit.setBuildingTarget(building)`），
  目前由敌人 AI 调用。敌人朝大本营推进，一旦走不到更近的地方，就锁定**挡路的那一段城墙**，
  **先贴到墙边、再一下一下拆**（不满足于"站在墙边发呆"）。
- **该拆哪一段**由 `path.js` 的 `findBlockingWallToward()` 决定，两个条件缺一不可：
  ① 这段墙必须挨着**敌人自己真的走得到**的区域（拆了才过得去）；
  ② 在候选里挑**离大本营最近**的。拆穿一段后可达区域扩大，下一次自然接着往大本营方向拆。
  所以无论玩家是围成一圈，还是拉一整条长墙把路线拦断，敌人都能自己找上门。
- 城墙打光后从网格与建筑表里一起摘掉（`removeBuilding`），**那一格立刻变成可通行**，
  敌人就从缺口走进来；日志会写 `城墙 (12, 7) 被 测试敌人 拆毁`，拆我方建筑时还会弹提示。
- 相关事件：`state.onCombatEvent({ type: 'buildingDown', building, source })`，
  由 `main.js` 负责收尸（`removeBuilding` + 计数）与写日志。

### 3. 资源（按占领地块实时增长）
- 两种资源：**粮食**、**黄金**。
- 每秒产出 = **己方占领地块数** × 1（`CONFIG.resource.foodPerTilePerSec` / `goldPerTilePerSec`）。
- HUD 实时显示数值与当前每秒速率。

### 4. 区块与占领【占位逻辑，等地图编辑器】
你的原话是"一大片地块归属在一个区块下，己方单位站在区块内持续一段时间后转为己方，
具体区块划分后续在地图编辑时给出，现在自由写占位逻辑"。当前实现：

- 把整张地图横竖**均分**成 `6 × 4 = 24` 个矩形区块（A1 ~ F4），每块 16 格。
- 区块状态：`无主` / `己方` / `敌方`；绘制上无主为暗黄、己方为蓝色、**占领中会从下往上填充黄色进度**。
- 己方单位站在无主区块内**持续 4 秒**（`CONFIG.zone.captureTimeSec`）即占领该区块；
  单位离开后进度每秒回退 0.6（`decayPerSec`）。多个单位同区块不叠加加速。
- 另有开关 `CONFIG.zone.zoneOwnedByBuilding`：区块内有己方建筑时直接归己方（默认开）。
- **后续替换点**：`js/zone.js` 的 `buildZones()` / `createZoneSystem()`。
  地图编辑器只要提供"每个地块属于哪个区块"的网格，其余逻辑不用改。

### 5. 将领
- 开局 3 个将领占位单位（快捷键 `1` / `2` / `3`），站在大本营附近。
- 按数字键快速选中并**把镜头移到该将领**；右键点击地图下达移动命令。
- 己方单位站在己方领地内会缓慢回血（方便肉眼确认领地归属是否生效，数值在 `unit.js`）。

### 6. 敌人
**本版按你的要求不做正式敌人。** 但城墙的阻挡、箭塔的伤害、单位的战斗逻辑都已经写好，
用侧栏「调试」面板可以刷**测试敌人**验证：

- ＋ 刷测试敌人 / 自动刷敌人 / 清除敌人（或按 `E`）。
- 测试敌人会朝大本营推进（A* 地块路线 → 换算成像素 → 拉直后走直线；
  旧版把地块坐标当像素坐标用，会一路走到地图左上角，现在有回归测试盯着）。
- **被城墙挡住时会贴到墙边把墙拆掉**（城墙有血量，见 2.5 节）—— 用来验证「城墙只挡敌方」。
  这条路上踩过三个坑，都留了回归测试，改 `updateEnemies()` / `nearestReachable()` 前先看一眼：
  1. **路径单位**：`findPath()` 给的是**地块**坐标，塞进 `u.path` 前必须换算成像素，
     否则敌人会朝地图左上角走；
  2. **`moveTo()` 的返回值**：原地不动时它也返回 `true`，所以不能只看它判断"是不是已经到位了"，
     否则敌人会站在墙边发呆（"到了就继续赶路"和"到了就找墙拆"要分开判断）；
  3. **可达性判定**：`nearestReachable()` 是"从目标往外扩圈找最近的空格"，
     必须加一层"从 `from` 真的走得到"的过滤（`reachableTiles()`）。
     旧实现没有这层过滤，BFS 第一圈就返回墙 / 山**另一侧**的格子 → `findPath` 必然失败 →
     敌人以为哪都去不了，于是**站在出生点一动不动**；同时"该拆哪段墙"只在身边 2 格内找，
     敌人离墙还有 9 格时也判定"没墙可拆"。两者叠加就是"用城墙拦住路线后敌人不动"这个 bug。
- 敌人也会参与警戒：它推进到位停下来之后，如果附近有我方单位就会主动接敌。
- 正式敌人接入时，只需替换 `updateEnemies()` 里的生成与 AI 逻辑。

### 7. 战斗与警戒（v0.3 新增）
数值全部集中在 `CONFIG.combat`，`CONFIG.combat.enabled = false` 可整体关掉（只留移动）。

- **攻击**：每个单位都有伤害、攻击距离、攻击间隔（默认都是近战 1 格）：

  | 单位 | 伤害 | 攻击距离 | 攻击间隔 | 生命 |
  |---|---|---|---|---|
  | 将领 | 26 | 1 格 | 0.9s | 200 |
  | 测试敌人 | 10 | 1 格 | 1.2s | 60 |

  开火时画一条攻击线，单位头顶出现小三角表示"正在交战"。
- **警戒（自动索敌）**：**没有攻击目标、且处于静止**的单位，会搜索警戒半径
  （`CONFIG.combat.aggroRange = 4` 格）内**最近的**敌方单位并锁定它。
  - 锁定后**先移动靠近**（追击），进入攻击距离就站住开火；
  - 追击期间目标一直在动，所以每 `CONFIG.combat.repathSec` 秒重新寻路一次，
    不会每帧重算；
  - **追击上限**：目标离"发现它的那个位置"超过 `aggroRange × leashFactor(1.8)`
    就放弃，不会一路追到地图另一头；
  - 目标死亡 / 被移出战场 → 自动脱离交战，回到警戒状态；
  - **玩家操作优先**：右键移动命令（`orderMove()`）会立刻中断交战。
- **两个阵营对称**：敌我共用同一套逻辑，静止的敌人也会盯上我方单位。
- **拆建筑**：单位也能把建筑当目标（`setBuildingTarget()`，敌人用它拆挡路的城墙）。
  规则和打单位一样 —— **先移动到攻击距离内，再一下一下打**；
  建筑占满整格，所以攻击距离额外算半格（贴墙就能砸到）。
  血量打光时 `takeDamage()` 返回 `false` 并广播 `buildingDown` 事件，
  由 `main.js` 把建筑从地图上摘掉（详见 2.5 节）。
- **选中面板**会显示攻击数值、警戒半径与当前交战对象；选中单位还会画出
  攻击距离（实线环）与警戒半径（淡环），交战目标套一圈红色虚线。
- 战斗事件（进入警戒 / 阵亡 / 建筑被拆毁）通过 `state.onCombatEvent` 回调进事件日志，
  我方单位阵亡、我方建筑被拆毁时还会弹提示。
