## 每一级具体差在哪

**大本营**（`base`）
* 3 级（现有）：主堡 + 露台栏杆 + 望楼（奶油色小亭）+ 红屋顶 + 旗，2.37 格高。
* 2 级：拿掉**望楼**，屋顶 / 旗杆整体下降 0.32 落到露台栏杆顶上 → 2.05。
* 1 级：再拿掉**露台（地板 + 栏杆）**，屋顶 / 旗杆再降 0.57 落到主堡顶 → 1.80。

**哨塔**（`tower`）
* 2 级（现有）：平台 + 栏杆 + **哨屋** + 红屋顶 + 旗。
* 1 级：拿掉**哨屋**（四面墙），屋顶 / 旗杆下降 0.32 落到栏杆上 = 露天哨台。

**警戒塔**（`watch_tower`）
* 2 级（现有）：石塔 + **挑廊 / 垛口** + 旗帜 + 门口的红色挂旗。
* 1 级：拿掉挑廊、垛口、旗杆与旗，只留平顶石塔（**保留门口的挂旗** —— 阵营色遮罩靠它）。

**粮田**（`farm`）
* 2 级（现有）：栅栏 + 两圈高麦 + **稻草人**。
* 1 级：拿掉稻草人 + 一圈高麦，只留矮苗（栅栏保留 —— 阵营色遮罩靠它）。

**矿脉**（`mine`）
* 2 级（现有）：岩体 + 木门框 + **五根矿晶**。
* 1 级：只留两根矿晶（贫矿 / 富矿的差别）。木门框保留（阵营色遮罩靠它）。

**房屋**（`house`）
* 1 级（现有）：单层半木结构小屋 + 红屋顶 + 烟囱。
* 2 级：墙体 / 立柱 / 腰线在 z 方向拉高到 1.5 倍（**门与窗不改尺寸**，窗子上移），
  屋顶与烟囱一起上移 0.45 → 2 层高的小屋（1.97 格）。

## 硬约束（改这些模型时别踩）

1. **1 单位 = 1 格，底边在 y = 0，原点在底面中心** —— 游戏按「格宽 × body_scale」统一缩放，
   高度完全由模型自己决定（见 `view/building_view_3d.gd` 文件头）。
2. **顶点色（`COLOR_0`）必须留着**：`rgb` = 材质原色，`a` = **阵营色遮罩**
   （`a = 1` 的部件吃阵营色）。**每一级都至少要保留一处 `a = 1` 的部件**，
   否则那一级在游戏里没有阵营色，敌我分不出来。本轮各模型保留的部件见上表括号。
3. **单个 mesh + 单个材质**（游戏会把 glb 里所有 MeshInstance3D 合并成一个 ArrayMesh，
   多材质也能合，但没必要）；三角面量级保持在这些数字附近（低模风格）。
4. **朝向**：模型是四向基本对称的；城墙才要求严格四向对称，这里的建筑没有正反面要求。

## 怎么再生成 / 继续加级

渲染与拼图：

```
python art_draft/_new_lowpoly/tiers/compose_sheet.py     # 需要 Pillow；输入是 tiers/*.png
```

`tiers/*.png` 是 Blender 正交渲染的单模型图（600×600，同机位 / 同光照；同一建筑的各级
共用同一个 `ortho_scale`，所以高度差可直接比）。输出：

* `art_draft/_new_lowpoly/tier_compare_base.png` —— 大本营 1 / 2 / 3 级
* `art_draft/_new_lowpoly/tier_compare_buildings.png` —— 其余五种建筑的 1 / 2 级

做法（Blender 里，任何一个模型都是这么拆的）：

1. 导入 `assets/models/<type>_lowpoly.glb`；
2. 按「顶点坐标相同」把面连成一件件 box（一个 box = 6 个面；glTF 顶点是拆开的，
   所以不能靠共享顶点，要按坐标合并）；
3. 按部件删：`bmesh.ops.delete(context='FACES')` 之后清掉孤立顶点；
   「屋顶 / 旗杆跟着往下坐」用**平移顶点**（`v.co.z += dz`）；
4. 导出 `export_scene.gltf(export_format='GLB', export_yup=True, use_selection=True)` ——
   `COLOR_0` 会自动带出来（导出后重新 import 一遍，确认 `color_attributes` 还在）；
5. 在 Godot 里 `--headless --import` 一遍（会生成 `*.glb.import`），
   再用 `load()` 检查每个 surface 都有 `ARRAY_FORMAT_COLOR`、`AABB.min.y ≈ 0`。

## 已经接上游戏（2026.11.17）

`view/building_view_3d.gd` 里新增了 `BUILDING_MODEL_LEVELS`（类型 → 等级 → glb 路径）：
大本营 1/2/3 → `base_l1 / base_l2 / base_lowpoly`；哨塔 / 警戒塔 / 粮田 / 矿脉都是
`*_l1` + 原文件当 2 级；房屋反过来（原文件 = 1 级、`house_l2` = 2 级）。
升级时换模型并播「放大 → 换模型 → 缩回」（`UPGRADE_POP_UP_SEC` / `UPGRADE_POP_DOWN_SEC` /
`UPGRADE_POP_SCALE`），所以**改文件名要同步改那张表**。

### 顶点色遮罩（2026.11.17 修复）

新分级模型导出时 `COLOR_0` 是 **VEC3**（没有 alpha）；游戏 shader 把缺失的 alpha 当 1，
于是整栋模型都被染成阵营色 —— 看起来就是「没有贴图」。
`tools/bake_building_vertex_mask.py` 会把它们的 `COLOR_0` 转成 **VEC4**，
并按同类型现有模型的「rgb → alpha」表补回遮罩（`a=0` 保留材质色、`a=1` 吃阵营色）。

```
python tools/bake_building_vertex_mask.py           # 只检查
python tools/bake_building_vertex_mask.py --write   # 写回 glb（然后 Godot --import）
```

`test_view3d` 现在会断言每一档模型都同时存在 `a=0` / `a=1` 顶点，避免再退回「整栋纯阵营色」。

## 没做的事

* **城墙分级**：木墙 / 石墙没有等级表，也没有分级模型（墙的升级是「木墙 → 石墙」）。
* **房屋 2 级是「拉高」而不是新增几何**：如果以后想要真正的二层楼（多一排窗、腰线），
  需要新做几何（复制一层墙 + 腰线再上移，注意接缝处别共面 z-fighting）。
* **美术上的 `body_scale`**：游戏按 `格宽 × body_scale` 统一缩放，所以模型尺寸改了以后，
  落地高度会跟着变（这正是「升级看起来更高」的来源），不需要另配高度。
