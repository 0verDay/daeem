## 1. 现在是什么样

- 手牌 / 科技牌都是**屏幕底部中央的一排扇形牌**（`UiLayoutRes.CARD_RECT = 539,803,842,277`，
  牌 142×206，悬停放大 1.6 倍、上抬 28px，同侧邻牌让开 42px）。
- 悬停说明现在写在**左下角那块说明牌**里（`view/hover_tip.gd`，377×260 固定框，
  离手牌很远，而且要盖住详情栏）。
- 卡牌数据已经够用：`recruit.list[].cost`、`building.<type>.cost/desc`、
  `tech.list[].line/desc`、`unit.unit_traits` / `unit.general_traits`。
  **缺的是"一句短描述"**（单位和将领没有风味文案，见 §5）。

## 2. 方案 A（最终版）

悬停哪张牌，就**固定在那张牌的左侧**浮出一块 300px 宽的说明牌，与牌留 26px 净距，
**面板顶边与卡面顶边对齐**（面板的背牌 / 投影 / 金色小菱形都留在这段缝里，
所以**不会压住被悬停的那张牌**；允许压别的牌）。
靠牌那条边挂一枚金色小菱形 + 一段引线，明确"这块是它的说明"。

**将领卡例外**：除左侧主面板外，牌右侧再开一块 236px 的「将领特性」面板
（标题 + 每条特性的名字 / 说明），同样顶对齐。其余卡牌只有左侧一块。

- 整屏：`01_insitu_unit.png`；放大：`01b_insitu_zoom.png`；右侧：`01c_insitu_right.png`
- 四类 + 置灰：`02_sheet_four_types.png`
- **最终布局（真机）**：`04_ingame_sheet.png`（含将领双面板）

版式（1:1，宽 300，高按内容 90~220）：

```
┌────────────────────────────────────┐  ← 切角纸牌：投影 + 两层错位背牌 +
│ 骑手                     [近战·骑兵] │     竖向渐变 + 2px 黄铜边 + 内圈金线
│ ────────────────                     │  ← 金线：整条淡 + 左端 34px 亮头
│ 粮食 80  │  黄金 160                  │  ← 9px 带字距标签 + 17px 亮金数值
│ ──────────────────────────────       │  ← 更淡的分隔
│ 轻骑突袭的骑兵，冲锋时撕开阵线；      │  ← 12px / 行高 18，深灰正文
│ 对步兵造成额外伤害，受远程伤害更少。   │
│ 特 性                                │  ← 只有将领有
│ [铁壁] [稳定]                         │
│ · 需 3 级大本营                       │  ← 只有置灰牌有（warn 红）
└────────────────────────────────────┘ ◆  ← 金色菱形指向卡牌
```

规格：

| 项 | 值 | 出处 |
|---|---|---|
| 宽 / 缝 | 300 / 26 px | `ui_layout.CARD_HOVER_PANEL_W / _GAP` |
| 内边距 | 15 px | 与详情牌一致 |
| 卡名 | 19 px `text` | 详情牌 18 → 略大一点，因为牌更小 |
| 类别标签 | 10 px `accent_bright`，胶囊 18 高 | 新样式，取自详情牌胶囊语言 |
| 造价格 | 标签 9 px 带字距 `text_faint` + 数值 17 px `accent_bright` | 详情牌数值格的紧凑版 |
| 描述 | 12 px / 行高 18 `text_dim` | 与 `hover_tip.BODY_*` 同档 |
| 特性胶囊 | 10 px、18 高、金描边 | 照 `hover_tip._draw_chips` |
| 置灰行 | 11 px `warning` | 照 `hover_tip` 的 note |
| 牌面 | 复用 `detail_v2.draw_plate()` | 同一份画法，样式天然一致 |

**为什么不是小的字+大框**：牌只有 90~220 高，行距和字号按内容长；
建筑 / 科技只有一两行，面板就矮（`02_sheet_four_types.png` 里能看出高矮差）。

## 3. 方案 B（备选）：左右双联

左牌放「名字 + 标签 + 造价」，右牌放「描述 + 特性」，卡牌夹在中间（`03_insitu_dual.png`）。

- 优点：单块牌更窄（236/258），信息分两摊，不用一块长牌。
- 缺点：**必然压住左右两侧的同伴牌**（左/右各 250 宽，手牌总共才 842 宽）；
  两张牌同时出现也更吵；牌在屏幕两端时一侧会出屏。要做得稳，得再写一套"哪边放得下"的分支。
- 结论：能做，但不如 A 干净；建议 A。

## 4. 位置规则（最终版）

```
card  = 悬停那张牌**放大后**的屏幕矩形（1.6 倍 + 上抬 28，实测 227×330）
主面板 x = card.left - 26 - 300          # 固定左侧（不再按左右半边换边）
主面板 y = card.top                      # 顶边与卡面顶边对齐
特性面板 x = card.right + 26             # 只有将领卡有，固定右侧
特性面板 y = card.top                    # 同样顶对齐
x/y 超屏时再 clamp(8, 视口 - 面板 - 8)     # 极端窗口兜底
```

- 26px 里放得下背牌（+9）、投影（~15）和指向卡的菱形（16），**面板加装饰都不压原卡**；
  同伴牌可以被压（用户口径允许）。
- 1920 宽下最左 / 最右的牌都放得下（300 + 26 + 236 + 26 = 588 < 屏宽）。
- 窗口缩放 / 换分辨率：按当前视口重算（`hud.view_size()`）。

## 6. 交互与"不挡别人"的保证

- 面板是 `MOUSE_FILTER_IGNORE` 的**纯显示**控件：鼠标命中的永远是底下的牌。
  它盖住哪张牌，鼠标移到那张牌上照样触发那张牌的 `mouse_entered`（这就是"可以遮挡、但不遮挡悬停逻辑"）。
- 面板**不是**卡牌的子节点（卡牌放大 1.6 倍时不会跟着放大 / 歪掉），挂在 `hud._root` 上。
  `z_index` 要压过牌：卡牌自身的 z 最高到 `CARD_SLOTS*2+4 = 22`（相对父节点累加），
  所以面板取 **30**（详情牌 5、旧悬停牌 6 都在它下面）。
- 出现：**等牌站稳**（抬起 / 放大 / 邻牌让开共约 0.165s ⇒ 0.18s 之后）再淡入 +
  从卡那侧滑出 10px（0.14s）；换牌只换内容不重播。牌没站稳就移开 / 换牌 / 拖牌 → 不弹。
- 收起：鼠标离开卡 / 切页 / **拖牌** / 手机长按松手。
- 手机：沿用现有长按弹详情的路径（`hud._lp_*`），长按哪个格就弹它旁边。

## 8. 已定的口径

1. 左下角旧悬停牌：**取代**（已删）。
2. 一句描述：先用**占位文本**（建筑写了示例；单位/将领自动拼；`dg_swordsman` 用你给的示例原话）。
   以后在单位 / 科技编辑器里暴露 `brief` 字段即可替换。
3. 位置：**固定左侧 + 顶对齐**；将领卡**额外**在右侧开一块特性面板。

范围：局内手牌 + 科技牌；备战 / 牌组界面的卡没动。
