# Taste
- When a request has missing details, ambiguity, or gaps in the prompt that would change the output, ask clarifying questions before writing any code or files rather than guessing. Confidence: 0.9
- Treat the project-root `README.md` as protected: do not edit, reformat, or delete it unless the user explicitly requests or approves it. Reading is fine. Silence is not approval. Confidence: 0.9
- Avoid packaging/bundling/distribution builds and screenshot or visual-regression tests unless explicitly requested or approved; prefer fast focused checks (unit tests, type-check, lint). Confidence: 0.9
- When packaging is explicitly requested, state the package artifact path(s) and how to use the package at the end of the final reply, not buried mid-response. Confidence: 0.9
- Communicates in Chinese; respond in Chinese, keeping code identifiers/paths in their original form. Confidence: 0.7
- Comfortable deferring visual/asset polish: happy to use crude placeholders (e.g. "just a small cube for now", or dropping in plain letter sprites as temporary unit art) in a first pass and refine the look later — doesn't expect polished assets to gate the mechanic. Confidence: 0.65
- Wants placeholder/temporary assets authored as generic, reusable components rather than bespoke one-offs — e.g. a placeholder decal explicitly meant to be dropped under any general and reused everywhere. Confidence: 0.55
- Prefers distinct, color-coded visual treatments for semantically different actions so the type is readable at a glance — e.g. green flag for a move order vs a yellow flag for a march order. Confidence: 0.5
- For visual effects, wants the real thing rather than a screen-space/overlay approximation — e.g. explicitly asked to reimplement a hit flash as a true per-pixel shader instead of a pasted white disc/rectangle, keeping the effect pixel-accurate (opaque texels recolor to white, transparent texels stay transparent). Confidence: 0.6
- Values game-feel feedback on gameplay events (e.g. proactively asks to add hit reactions to units and buildings), but wants such effects restrained and brief — a white flash plus only a slight, short left-right shake, not exaggerated motion. Confidence: 0.5
- Bug fixes ship with a regression test that reproduces the exact reported scenario, and the test must be proven to actually catch the bug — temporarily disable the fix, confirm the assertion goes red, then restore it. Confidence: 0.6
- Prefers narrow, surgical fixes scoped to the exact failure path over broad fixes that alter shared behavior; narrows the change when it breaks unrelated existing tests. Confidence: 0.5
- When integrating new art/asset files, prioritizes gameplay readability and existing visual conventions over faithfully reproducing the asset's own colors — e.g. chose "faction-color silhouettes" (recolor the asset's shape by faction, thicker outline for leaders) so friend/foe stay distinguishable, rather than keeping the asset's original palette. Confidence: 0.5
- When offered a visual trade-off between options, leans toward the smoother, higher-quality rendering over cheaper approximations — e.g. chose smooth semi-transparent building fade over a dithered "ghost" or whole-building-hide approach, accepting the extra cost (re-entering the transparent pipeline and adding depth handling). Confidence: 0.45
- Reviews how things actually appear on screen and reports visual defects (e.g. sprites rendered upside-down); expects such defects fixed by inspecting real rendered output rather than trusting existing code comments or a green test suite — passing tests alone don't prove visual correctness. Confidence: 0.5
- Visual/game-feel tunables (opacity, color, timing, size) are expected to be exposed as config entries with a documented entry and a sensible default, not hardcoded constants — e.g. decal opacity as `render.general_decal_alpha` (0.5), selection ring color/alpha/duration/start-scale as `render.selection_ring_*`; values are clamped on read. Confidence: 0.5
- Prefers state-change indicators to animate in/out with a short, restrained transition (e.g. scale-in + fade-in) rather than popping instantly, and expects the animation to play in reverse on the opposite transition (e.g. deselect plays the appearance animation backwards). Confidence: 0.5
- Wants new visual elements sized/styled to match the existing related element for consistency, and expresses this in terms of the current on-screen element (e.g. a new selection ring must animate down to exactly the same size as the existing base decal). Confidence: 0.5
