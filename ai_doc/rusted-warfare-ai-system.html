Rusted Warfare 1.15
AI 系统逆向分析

这份文档解释 Rusted Warfare 遭遇战 AI 的实际工作方式：它如何调度、如何赚钱和建造、 如何编组、如何选择目标、难度如何生效，以及地图和 Mod 能怎样改变它。 所有结论来自对 game-lib.jar 的静态反编译与交叉验证。

反编译 1698 类 代码量 约 17 万行 语言 Java 8 引擎 LWJGL 2.9.3 + Slick2D AI 包 com.corrodinggames.rts.game.a
静态分析，无运行时调试 混淆名保留原样，推断内容单独标注 时间单位：60Hz 逻辑帧

01摘要

Rusted Warfare 的 AI 不是行为树，也不是神经网络。它是一个典型的 规则驱动 + 效用评分 + 随机权重 + 有限状态机 系统。

三层结构

战略层负责经济/生产，编组层负责基地与军队，执行层通过命令接口驱动单位。

预算制生产

AI 不按固定 build order 排队，而是用“生产预算 + 加权评分”决定造什么。

随机目标

攻击组从全局敌方单位表中随机挑选主目标（对内置单位），没有独立侦察模块。

难度=经济

难度主要改变 AI 收入倍率；Impossible 额外提高建造节奏与编组上限。

核心结论 AI 的“聪明”来自多层规则和参数，而不是搜索或学习。它的行为可以被总结为： 先保证经济与基地，再按地图连通性选择兵种，按预算持续生产，最后把闲置单位编成 攻击/防御/运输组，用随机敌方单位作为目标发起进攻。
问题结论
AI 会侦察吗？没有独立的侦察/探索模块。对内置单位，目标选择直接遍历全局敌方单位表。
AI 会优先打基地吗？不会优先。攻击组从所有敌方单位中随机选目标，指挥中心只是候选之一。
难度改单位属性吗？不直接改。主要改收入倍率，Impossible 额外改建造/生产/编组上限。
AI 会运输吗？会。陆军无法到达目标时，单位会进入运输等待组，由运输组运送。
Mod 能改 AI 吗？能。单位 [ai] 段、地图 team_info、AI 插件层都可以影响行为。

03总体架构

AI 系统可以分成三层：战略层决定“做什么”，编组层决定“谁去做”，执行层通过统一命令接口把动作交给单位。

战略层

AI 玩家 game.a.a：计时器、经济、建造、生产、编组、难度。

编组层

i 基地组、g 战斗组、n/l 运输组，负责“谁去做”。

执行层

命令接口 gameFramework.e → 单位状态机 → 寻路/碰撞/攻击。

04运行节奏与调度器

AI 主循环在 game.a.a.a(float f2)。参数 f2 的单位是 60Hz 逻辑帧，不是秒。引擎每帧大约把它按 16.666666 换算成毫秒计数器，所以：

1 帧 ≈ 16.7 ms 25 帧 ≈ 0.42 s 80 帧 ≈ 1.33 s 250 帧 ≈ 4.17 s 800 帧 ≈ 13.3 s 17000 帧 ≈ 283 s
周期内部计时器动作
每帧a(float)处理首次运行、基地连通性分析、计时器累加、调用父类收入逻辑。
25 帧aP把累积时间分给编组；挑最多 2 个“饥饿”编组执行 b() / d()。
80 帧aLn()：刷新编组、分配闲置单位、创建基地/攻击/防御/运输组、处理基地受攻击。
250 帧aNm()：统计单位、运行 AI 插件、选生产目标、发建造/升级命令、创建扩展基地/工兵组。
1000 帧byAI 调试/维护周期（每 1000 帧检查单位数量、清理异常单位）。
 
// game.a.a — 简化后的主调度
void a(float dt) {
    super.a(dt);                 // 收入倍率、玩家基础逻辑
    if (disabled || defeated) return;

    if (firstRun) {
        findCommandCenter();
        testLandAndHoverConnectivity();
    }

    aP += dt;
    if (aP > 25)  { updateStarvedGroups(); aP -= 25; }

    aL += dt;
    if (aL > 80)  { n(aM); aL -= 80; }

    aN += dt;
    if (aN > 250) { m(aO); aN -= 250; }
}
为什么不是每帧都做全部决策 战略层的建造/生产/编组成本较高，AI 用低频计时器摊开；编组层和高频单位逻辑仍然逐帧运行。 这既降低 CPU 开销，也让 AI 的决策带有明显的“节奏感”。

命令接口

AI 通过 l2.cf.a(this.R) 取得一个命令构造器，然后调用 a(unit)、a(x, y)、a(target)、a(action) 等方法。 命令最终进入 gameFramework.e，由单位执行。这样 AI 不需要直接操作单位坐标， 也不会绕过寻路、碰撞和攻击规则。

设计含义 因为 AI 走的是和玩家相同的命令路径，它在多人/回放中天然具有确定性； AI 的“操作”也会像玩家一样被记录、校验和重放。

06经济、建造与生产

AI 的经济核心不是“攒钱买固定套餐”，而是“收入 → 建造评分 → 生产预算 → 批量下单”。

6.1 收入与难度倍率

AI 玩家的收入在 game.n.b(float) 中计算：

float E() {
    int diff = C();                     // aiDifficulty
    float mul = 1.0f;
    mul = diff > 0 ? mul + diff * 0.4f
                     : mul + diff * 0.3f;
    if (diff == 3) mul += 1.5f; // Impossible
    return mul;
}

void b(float dt) {
    if (!isAI) { c(dt); return; }
    c(E() * dt);                          // AI 收入倍率
}

6.2 建造优先级评分

i.c() 会遍历所有单位类型，按当前全局数量、本基地数量、工厂数量、资源给出一个分数， 选择最高分；有 1% 概率随机选一个次优项，避免每局完全一样。

seaFactory水图且没有时约 0.3；随后约 0.1 / (n3 + n4·2)。

6.7 科技升级

科技升级不是固定顺序。AI 会在资金和工厂/单位数量达到条件时，从可用升级动作中按概率挑选。 代码里有多个资金阈值（约 1300 / 1700 / 2100 / 2800 / 3100 / 4800 / 8000 …）， 以及“没有某种单位时提高优先级”的修正。

注意 这里的“优先级”不是严格概率，而是评分。AI 会选最高分，只在 1% 情况下随机选次优。 因此它既不是完全固定，也不是完全随机。

07基地组：game.a.i

基地组是 AI 的经济与建造核心。它管理一组工兵/工厂，负责造建筑、造单位、扩张和防御。

k.a 主基地

围绕 Command Center 创建，默认状态 j.c。负责基础经济、工厂、防御和单位生产。

k.b 扩张基地

在地图出生点/资源点创建，初始状态 j.a，约 2000 帧后转为 j.c。

k.c 工兵/前哨组

从已有单位位置创建，用于向前推进建造或补充工兵。

命名说明 k.a / k.b / k.c 的语义是根据创建位置、后续调用和调试输出推断的； 原始源码中的枚举名已被混淆，不能从字节码直接恢复。

7.2 生命周期

  1. 创建主基地组：如果没有任何基地组，优先在 Command Center 位置创建；没有 CC 则退而求其次找可建造单位。
  2. 分配工兵：把闲置工兵、可建造单位分配到基地组；工兵数量不足时从其他基地组“借”。
  3. 寻找建造位置：i.a() 在基地半径内扫描资源块/可建造地块，给 Extractor 等建筑找落点。
  4. 选择建造目标：调用 i.c() 得到当前最高优先级建筑/单位；i.g(as) 检查工兵、价格、可建造性后发命令。
  5. 生产单位：i.v() 根据预算和移动类型权重批量训练单位；每次成功训练扣 1 点预算。
  6. 扩张：在地图出生点创建新的 k.b 基地组；同一区域最多保留有限数量，重叠时删除状态更低者。
  7. 防御：检测基地附近敌人，命令范围内单位攻击；低血量单位撤退；基地长时间无单位则废弃。

7.4 基地选址检查

扩张/新建基地时，AI 会检查：

  • 290 范围内没有敌方单位（a(point)）。
  • 490 范围内没有其他基地组（避免重叠）。
  • 160000 平方距离（约 400）内没有已用出生点。
  • 地形可通行，且不在液体/不可建造区域。
  • 如果已有多个基地组，会优先选择远离现有基地的出生点。

8.2 各阶段细节

选目标

w = R.as()。`as()` 会遍历全局单位表，过滤掉死亡、非敌方单位， 然后随机返回一个。它不会优先指挥中心、炮塔或高价值单位，也不要求目标在视野内。

集结

h() 在目标附近计算集结点：

  • 基础距离 50–720，至少 450；
  • 80% 概率加 ±110° 角度扰动；
  • 80% 概率在距离上再加随机偏移；
  • 用 a(x, y) 和 R.a(unit, x, y) 检查每个单位能否按自己的移动类型到达；
  • 不能到达的单位加入 G，等待运输组。

集结期间如果任何单位在最近 1000 帧内受到伤害，AI 会取消集结，避免在火力下站桩； 如果集结超过 17000 帧（约 283 秒），则直接转入进攻。

进攻

  • 每 800 帧（约 13.3 秒）重新下发一次攻击命令。
  • 只命令能到达主目标的单位；无法到达的单位留在 G。
  • 如果没有任何单位能到达，放弃本次进攻。
  • 如果组内少于 3 个单位且已过 1000 帧，解散。
  • 如果进攻超过 11000 帧（约 183 秒），解散。

8.3 防御组

防御组围绕关联基地活动，逻辑更保守：

  • 如果基地被攻击，找基地附近的敌人并回防。
  • 如果敌人太强，向随机方向撤退，避免全军覆没。
  • 基地组 i.i() 会命令基地半径内单位攻击靠近的敌人。
  • 防御组数量与基地数量、单位数量相关，有上限。
行为特征 攻击组的目标是“随机敌方单位”，再加上集结/受伤取消机制，所以实战中会出现： 小股部队反复集结、被擦伤就撤退、绕过近处军队去打远处单位、以及长时间不进攻。 这是规则设计的结果，不是 bug。

09运输组：game.a.n / game.a.l

当陆军无法通过地形到达目标时，AI 会尝试用运输单位把部队送过去。运输逻辑分两层：

l：等待运输组

保存暂时无法到达目标的单位。单位距离组中心超过 3600，或组为空/超过 5000 帧，就会解散。

n：运输组

寻找运输单位、装载 l 组中的单位、移动到目标附近并卸载；支持飞行/非飞行运输。

战斗组的 G 列表会收集“无法到达主目标”的单位；运输组从这些列表和 l 组中取货。运输组本身也会检查运输单位是否存活、是否已被占用， 并在没有运输单位时自动解散。

是否启用运输由地图连通性决定：ai() 表示需要运输，aj() 表示需要悬浮运输。基地组会按 R.ai() 条件和运输组数量决定是否生产运输单位。

10目标选择与地图知识

这是这套 AI 最容易被玩家感知、也最容易被误解的部分。

10.1 目标池是全局敌方单位

// game.a.a — 目标选择
public am as() {
    int count = 0;
    for (am u : am.bE) {              // 全局单位表
        if (u.dead || u.cN != null || u.u()) continue;
        if (!this.c(u.team)) continue;  // 只要敌方
        if (!this.j(u)) continue;       // 目标有效性
        count++;
    }
    // 随机返回其中一个
}

public boolean j(am u) {
    return u.cg() || !this.c(u.bX);
}

在基类 units.am 中，cg() 直接返回 true； game.n.c(team) 判断“是否敌方”（this.r != other.r）。 因此对内置单位来说，j() 几乎不会过滤视野。

关键结论 AI 的主目标选择实际上拥有全局敌方单位表（对内置单位）。它没有独立的侦察/探索模块， 也不会因为战争迷雾而看不到目标。这解释了为什么 AI 会攻击远处随机单位。

10.2 地图连通性预计算

首次运行时，AI 会从自己的 Command Center 出发，测试到敌方基地/出生点的路径：

  • ao.b：普通陆军；
  • ao.f：悬浮/两栖；
  • 结果写入 bh、bi、bj、bk 等标志；
  • ai()/aj() 根据这些标志决定是否使用运输；
  • i.v() 用这些标志调整陆军/悬浮/空军生产权重。

12.3 AI 插件层

AI 有一个可插拔组件层：game.a.a.a，通过 game.a.a.bJ 列表挂载。当前版本能确认的内置插件是核弹控制器 game.a.a.d：

  • 通过 aiTags: nukeLauncher 找到核弹单位；
  • 用 f.a(..., e.f) 选择发射动作；
  • 用 R.at() 选一个随机敌方位置；
  • 在 b(float) 中周期性尝试发射/攻击建筑。

插件会随存档序列化（a.a.a 的 a(as)/a(k)）， 并通过 a.a.b 枚举恢复；这解释了为什么某些 AI 行为会出现在存档/回放状态里。

12.4 生存模式

地图 map_info.type=survival 时会走另一套节奏：

  • 波次间隔约 1200 帧；低难度时约 3000 帧。
  • survivalWaves 定义波次内容；survivalWavesClassic 选择经典波次。
  • AI 玩家的 U 标志为真，主循环进入生存分支：周期性集结、选择目标、派兵。
  • 胜利条件可以是 requiredObjectives、commandCenter 等。

13战役与脚本 AI

遭遇战 AI 和战役 AI 不是同一套东西：

类型驱动方式
遭遇战 / 沙盒game.a.a 的规则 AI，本文主体。
生存模式复用规则 AI，但由 map_info 的波次配置和 U 标志驱动。
战役任务MissionEngine + 地图 triggers 层；脚本触发器负责剧情、增援、目标。

战役地图通常会在 triggers 对象层里定义任务逻辑。AI 玩家仍然可能存在， 但它们的行动会受到触发器、team_info 和地图脚本的共同约束。 因此“战役 AI 很难/很聪明”往往来自脚本编排，而不是遭遇战 AI 本身。

14行为特征与局限

做得好的地方

  • 经济、建造、扩张、防御、运输、核弹都有完整规则。
  • 会按地图连通性选择陆军/悬浮/空军。
  • 攻击组会集结、等待、受伤取消、超时进攻。
  • 难度可以通过经济倍率平滑调整。
  • Mod 可以深度参与 AI 生产权重和特殊行为。

明显局限

  • 没有侦察/战争迷雾探索模块。
  • 主目标是随机敌方单位，不优先指挥中心或高价值目标。
  • 生产是加权评分 + 随机，不是固定 build order。
  • 编组时间阈值较长，容易出现小股部队送人头。
  • 难度主要是经济倍率，不是战术智能。

玩家感知到的典型行为

现象代码层面的原因
AI 越过近处军队去打远处单位as() 从全局敌方单位中随机选主目标。
AI 在玩家基地附近反复徘徊攻击组集结/受伤取消/重新选点，目标可能已死亡或不可达。
AI 长时间不进攻攻击组需要攒够单位、等待集结计时，且可能被伤害打断。
AI 经济突然爆发难度收入倍率 + 生产预算 + 多基地扩张叠加。
AI 会跨海进攻陆军不可达时进入运输等待组，运输组负责运送。
给 Mod 作者的建议 如果你希望 AI 更偏向某种单位，优先调 [ai] buildPriority 和 recommendedInEachBaseNum，而不是改单位价格；价格只影响“能不能造”， 权重才影响“想不想造”。如果希望 AI 优先攻击建筑，需要修改 as() 的目标过滤逻辑， 这不是数据能直接做到的。
